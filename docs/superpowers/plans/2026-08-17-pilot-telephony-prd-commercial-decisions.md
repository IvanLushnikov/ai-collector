# План обсуждения: телефония, гейты PRD и коммерция пилота

Дата: 17.08.2026  
Статус: пакет для решения, не план кодирования live-телефонии  
Владельцы встречи: продукт + коммерция + инженерия; legal/ИБ — отдельные слоты по блокерам

**Цель:** закрыть решения, без которых нельзя честно продавать и запускать Controlled Pilot: канал звонка, обязательные ответы PRD, технический контур и цена.

**Как пользоваться:** идём по разделам сверху вниз. Каждый вопрос — решение или явный перенос с датой. После встречи ответы переносятся в PRD / ADR / rulebook, а не остаются только в этом файле.

**Не делать на этой встрече:** писать адаптер Exolve, поднимать LiveKit, менять биллинг в коде. Сначала решения.

Рабочая гипотеза инженерии на вход во встречу (можно сменить явным решением):

1. Пилот: платформенный **Exolve Voice API**, клиент даёт только направление перевода.
2. «Любая SIP» — после пилота, через шлюз в РФ, не OpenAI и не Asterisk.
3. Манго — партнёр онбординга и запасной CPaaS, не мозг диалога.

## 1. Решения по телефонии

Открыть HTML-таблицу и зафиксировать вердикт по строкам.

- [ ] **T-TEL-1.** Канал пилота: платформенный Exolve / клиентский Манго / иное. Если иное — какая строка таблицы.
- [ ] **T-TEL-2.** Что клиент вставляет в кабинет в v1: ничего (только номер перевода) / ключ API / host+password SIP / оба слоя API+SIP.
- [ ] **T-TEL-3.** Универсальный BYO SIP (LiveKit в РФ): в пилот / в SaaS v1 / в Scale / не обещаем в продаже до отдельного ADR.
- [ ] **T-TEL-4.** OpenAI Realtime SIP: только внутреннее демо на тестовых номерах / не используем вовсе.
- [ ] **T-TEL-5.** Робот Exolve/Mango: подтвердить запрет как мозг продукта (уже ADR 0003).
- [ ] **T-TEL-6.** Handoff в пилоте: только E.164 / E.164+SIP URI очереди клиента.
- [ ] **T-TEL-7.** Кто платит минуты оператору в пилоте: мы (платформа) / клиент на своём договоре / гибрид.
- [ ] **T-TEL-8.** Нужно ли менять ADR 0003 (Exolve как цель) и ADR 0005 (BYOK телефонии нет в v1) по итогам T-TEL-1…3.

Критерий закрытия раздела: одна выбранная строка для пилота, список того, что нельзя обещать сейлзу, дата пересмотра BYO SIP.

## 2. Вопросы PRD, на которые надо ответить

Источник: [prd-open-questions.md](../../product/prd-open-questions.md) и раздел 21 PRD. Не выдумывать юридический факт; спорное — в пакет юристу.

### 2.1. Compliance и legal

- [ ] **P-L-1.** Какие нормы РФ в v1 — системный lock, а не общая фраза (окно, 1/2/8, disclosure, suppression, маркировка)?
- [ ] **P-L-2.** Какие сценарии engine блокирует без override (нет «позвонить всё равно»)?
- [ ] **P-L-3.** Что клиент может сузить, что нельзя выключить в UI?
- [ ] **P-L-4.** Нужны ли разные rulebook-профили (МФО / банк / ПКО) уже в пилоте?
- [ ] **P-L-5.** Как юристы закрывают коллизию ст. 44.1‑1 закона о связи и ФЗ‑230 для портфеля пилотного клиента? Без memo live = нет.
- [ ] **P-L-6.** Что считать состоявшимся контактом для 1/2/8: `ringing`, ответ, диалог, voicemail, короткий сброс?
- [ ] **P-L-7.** Покрывает ли согласие в договоре займа автоматические вызовы? Статус `pending` в пилоте = блок?
- [ ] **P-L-8.** Срок хранения записи/транскрипта для нашей роли платформы (ориентир продукта ≥ 1,5 года — подтвердить).
- [ ] **P-L-9.** Кто юридически инициирует вызов: кредитор, платформа, оператор связи?

### 2.2. Stop conditions и автопауза

- [ ] **P-S-1.** Точный перечень событий автопаузы. База уже есть: `compliance_violation`, `complaint_spike`, `recording_failed`, `handoff_overloaded`, `provider_sla_failed`. Что добавляем/убираем?
- [ ] **P-S-2.** Что такое исчерпание попыток контакта?
- [ ] **P-S-3.** Автопауза при низком ASR/confidence — да/нет, какой порог?
- [ ] **P-S-4.** Кто возобновляет после автопаузы, каким чеклистом (уже есть задел safe-resume)?
- [ ] **P-S-5.** Численный пол порогов: системный минимум vs настройка клиента.

### 2.3. Метрики и экономика пилота

- [ ] **P-E-1.** Чем меряем снижение затрат: операторские часы / стоимость контакта / полная unit economics?
- [ ] **P-E-2.** Baseline: ручной обзвон / аутсорс / текущий автодозвон клиента?
- [ ] **P-E-3.** Численные KPI успеха пилота (нарушения = 0 уже в PRD; остальное — числа).
- [ ] **P-E-4.** Нагрузка на операторов: звонки, часы, FTE или длина очереди handoff?
- [ ] **P-E-5.** Успех звонка в отчёте пилота: подтверждение контакта и PTP — достаточно или нужны ещё поля?

### 2.4. Качество voice/AI

- [ ] **P-Q-1.** Чем подтверждаем качество ASR: golden set, WER на обезличенном корпусе, экспертная оценка?
- [ ] **P-Q-2.** Порог confidence → handoff. Число или «пока экспертно, не в live»?
- [ ] **P-Q-3.** Обязательные handoff кроме «спорно»: третье лицо, угроза, запрос человека, спор долга, низкий ASR?
- [ ] **P-Q-4.** Жёсткая state machine в первом live — да (рекомендация ADR 0004) / свободный диалог запрещён?

### 2.5. Scope v1 и UX-путь

- [ ] **P-V-1.** Встроенные сценарии кроме PTP: только первый контакт / ещё что?
- [ ] **P-V-2.** Ручное добавление контакта в v1 или только CSV/Excel?
- [ ] **P-V-3.** Какая статистика обязательна в отчёте v1, какая — этап 2?
- [ ] **P-V-4.** В UI звонка: только транскрипт / транскрипт + структурированный outcome?
- [ ] **P-V-5.** Аудио в UI v1: нет (как PRD) / только роли QA/compliance?
- [ ] **P-V-6.** Приоритет UX-разрывов T-065: auditable launch, причины readiness, proof chain звонка — подтверждаем как блокер пилота?

### 2.6. Операционная модель

- [ ] **P-O-1.** Кто у нас разбирает спорные звонки и правит сценарий на пилоте?
- [ ] **P-O-2.** Ежедневный ручной QA: доля выборки?
- [ ] **P-O-3.** Смена сценария: только новая версия, running не трогаем (уже в коде) — ок для продажи?
- [ ] **P-O-4.** Граница self-service vs managed service в первом релизе: клиент сам грузит базу и жмёт запуск / мы ведём пилот руками?

Критерий закрытия раздела: по каждому ID ответ, «юристу», или «не в v1» с отсылкой в backlog.

## 3. Технические вопросы

Опираться на карту технологий и текущий код: sandbox adapter есть, боевого провайдера нет, `T-149` (HTTP Exolve) заблокирован до DPA.

- [ ] **T-1.** Подтверждаем стек пилота: Fastify + PG + sandbox сейчас; live = один адаптер Exolve за feature-flag `LIVE_CALLS_ENABLED`.
- [ ] **T-2.** Probe production-соединения обязан включать marking + recording + handoff, не только SIP 200. Какие ещё сигналы (AMD, CDR)?
- [ ] **T-3.** Секреты телефонии: только env/secret manager (как сейчас задумано) или ciphertext как у BYOK речи, если появится ключ клиента?
- [ ] **T-4.** Запись: объектное хранилище в каком облаке РФ (Yandex / Selectel / Cloud.ru)? Кто платит storage в пилоте?
- [ ] **T-5.** Когда вводим Redis + BullMQ: до первого live-обзвона или можно синхронный старт на крошечном пилоте?
- [ ] **T-6.** Лимит одновременных линий: откуда число — квота Exolve, настройка кампании, оба min()?
- [ ] **T-7.** Идемпотентность webhooks телефонии и сверка CDR ↔ usage — обязательны до live или достаточно ручной сверки на 1 клиенте?
- [ ] **T-8.** SpeechKit + YandexGPT: ключ платформы на пилоте или сразу BYOK клиента?
- [ ] **T-9.** Хостинг пилота: конкретный регион и кто администрирует.
- [ ] **T-10.** Субподрядчики в поручении 152‑ФЗ: список (хостинг, телефония, ASR/TTS, LLM, object storage).
- [ ] **T-11.** Нужен ли отдельный стенд «один тестовый номер команды» до любого клиентского live?
- [ ] **T-12.** Меняем ли PRD-формулировку «без автоматических интеграций с новой клиентской телефонией», если продажа обещает BYO SIP?

Критерий закрытия раздела: список работ в `TECH_BACKLOG_1SP.md` после решений, без новой «большой» разработки до выбора T-TEL-1.

## 4. Бизнес и цена

Публичные ориентиры рынка (не наши цены, проверять КП): Exolve Robots от ~6,5 ₽/мин AI; Манго робот ~4,5 ₽/мин; Zvonobot от ~2 ₽/мин; Fromtech от ~2,25 ₽/мин. В калькуляторе `index.html` модельные COGS: telecom 1,35 / platform 1,20 / ASR 0,60 / TTS 0,45 / LLM 0,90 ₽ на минуту соединения плюс маркировка и storage. Это иллюстрация, не прайс.

### 4.1. Что продаём и за что берём деньги

- [ ] **B-1.** Единица прайса клиенту: ₽/connected minute / ₽/успешный диалог / пакет минут / подписка + usage / гибрид. Биллинг v0 уже умеет три единицы учёта.
- [ ] **B-2.** Что входит в «всё включено», что отдельно: телефония, маркировка, ASR, TTS, LLM, хранение, внедрение, поддержка.
- [ ] **B-3.** Пилот: 0 ₽ / себестоимость / скидка / полная цена. Срок и потолок минут/звонков.
- [ ] **B-4.** Setup / внедрение: берём или нет; ориентир калькулятора 900 000 ₽ implementation + 700 000 ₽ integration — оставить как модель или заменить?
- [ ] **B-5.** Поддержка и account: отдельная строка (в калькуляторе 160k + 120k ₽/мес) или в подписке?
- [ ] **B-6.** BYOK речи: минуты SpeechKit/YandexGPT клиента не входят в наш invoice (уже ADR 0005). Подтверждаем для продажи?
- [ ] **B-7.** Если клиент на своей телефонии: наша цена только за «мозг» (ASR/TTS/LLM + платформа) или всё равно ₽/мин диалога?

### 4.2. Себестоимость и маржа

- [ ] **B-8.** Целевая contribution margin пилота: какое GM% считаем «можно масштабировать»?
- [ ] **B-9.** Фиксируем внутренний учёт COGS раздельно: telecom, ASR, TTS, LLM, storage, infra, marking. Кто ведёт таблицу факта после стенда?
- [ ] **B-10.** Handoff: не наш COGS, но лимит нагрузки на операторов клиента — входит ли в KPI пилота и в договор (SLA очереди)?
- [ ] **B-11.** Не обещать в КП цифры TAM/ROI из старого концепта (в `index.html` они помечены как неподтверждённые).

### 4.3. Партнёрки и кто платит оператору

- [ ] **B-12.** Манго как партнёр PRD: рефералка, совместный пилот, или только «клиент сам покупает ВАТС»?
- [ ] **B-13.** Delfin: что именно в пилоте (интеграции), есть ли доля в выручке?
- [ ] **B-14.** Если платформенный Exolve: мы перевыставляем минуты 1:1, с наценкой, или прячем в bundled ₽/мин?
- [ ] **B-15.** Риск антиспама/блокировки АОН: кто несёт простой кампании и штрафы по договору?

### 4.4. Сделка пилота

- [ ] **B-16.** Типовой ICP первой сделки: средняя МФО, DPD 1–30, какой объём базы?
- [ ] **B-17.** Economic buyer и кто подписывает DPA / поручение на обработку.
- [ ] **B-18.** Критерии GO/NO-GO пилота в договоре: 0 подтверждённых нарушений + какие ещё числа из P-E-3.
- [ ] **B-19.** Что сейлз имеет право обещать по SIP «вставите host/pass» до отдельного ADR. Рекомендация входа: не обещать.

Критерий закрытия раздела: черновик коммерческого предложения пилота (единица, состав, кто платит минуты, потолок) и список запрещённых обещаний.

## 5. Порядок встречи (90–120 мин)

1. 10 мин — HTML-таблица, снять «любая SIP в v1 или нет».
2. 25 мин — legal/PRD блокеры live (P-L-5…9). Если нет слота юриста — зафиксировать hard gate и не спорить про формулировки.
3. 20 мин — канал телефонии и деньги за минуты (T-TEL + B-7, B-12, B-14).
4. 20 мин — KPI пилота и прайс (P-E + B-1…5).
5. 15 мин — техника: probe, запись, стенд, субподрядчики (T-2, T-4, T-10, T-11).
6. 10 мин — список «не обещать» и следующие ADR/правки PRD.

Если времени мало: обязательны T-TEL-1, P-L-5, B-1, B-3, B-7. Остальное — письменный follow-up.

## 6. Куда переносим ответы

| Решение | Куда писать |
|---|---|
| Канал пилота и запрет робота | ADR 0003 (правка или 0006) |
| BYO SIP / ключ клиента | новый ADR или правка 0005 |
| Нормы и 1/2/8 | rulebook + legal memo, не сразу в код |
| KPI и baseline | PRD §16 |
| Прайс и единица | billing-model + коммерческий one-pager (ещё нет файла) |
| Обещания SIP в продаже | PRD §9 границы + PRODUCT_LANGUAGE |
| Работы в коде | TECH_BACKLOG_1SP.md, не больше одного 1 SP за итерацию |

После встречи: обновить этот файл статусом «решения зафиксированы / дата», проставить ответы под чекбоксами, не оставлять расхождение с ADR.
