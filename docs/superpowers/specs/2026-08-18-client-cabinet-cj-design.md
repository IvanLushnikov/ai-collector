# Кабинет клиента: канонический путь и IA

Дата: 18.08.2026  
Статус: утверждена 18.08.2026; можно реализовывать клиентский кабинет  
Поверхность: клиентский кабинет (`prototype.html`).  
Не входит: продуктовый дашборд `index.html`.

Главный принцип продукта не меняется: автоматизировать только то, что система может безопасно выполнить, объяснить и доказать. Юридические лимиты, окна звонка и основания контакта не придумываются в этой спецификации. Обхода запрета звонка кнопкой «позвонить всё равно» нет.

## 1. Зачем

Сейчас кабинет состоит из многих разделов и дублирующих кнопок, но у менеджера нет одного очевидного пути. Одни и те же действия ведут в разные ветки («Открыть», «Отчёт», «Открыть причину», «Запуск», «Проверка», «Настройки»).

Нужно собрать **один канонический путь менеджера кампаний** и подчинить ему меню, вкладки, кнопки и русский текст.

## 2. Пользователь и язык сущностей

| Роль | Где работает |
|---|---|
| **Менеджер кампаний** (основной) | Весь клиентский кабинет этого документа |
| Руководитель взыскания | Тот же кабинет; отдельных экранов «для руководителя» в этой волне нет. Аналитика и журнал ему тоже понятны |
| Наша компания (разработка / админ) | Отдельный контур. В клиентский кабинет не входит |

В исходных комментариях «company» = **кампания**, не организация-клиент. Организация показывается в шапке как имя аккаунта.

Внутренние имена кода (`Campaign`, `CallAttempt`, `ComplianceDecision`) в UI не показываются. Соответствие — в разделе 10 и в `PRODUCT_LANGUAGE.md` (словарь обновляется в той же волне, что и тексты).

## 3. Канонический путь

Один сценарий, слева направо:

**Создать кампанию → база → сценарий → телефония → запустить → звонки → аналитика**

Правила пути:

1. Следующий шаг всегда один и называется одинаково, откуда бы ни вошли.
2. Незаполненный шаг не маскируется зелёной галочкой.
3. Запуск — не отдельный раздел, а действие в шапке **Обзора**, после базы, сценария и телефонии.
4. Аналитика смотрит на все кампании; внутрь одной кампании попадаем фильтром, не отдельным «Отчётом».
5. Журнал действий — доказательная лента действий **сотрудников клиента**, не операционный экран кампании.

Создание новой кампании: имя и основные поля → сразу вкладки той же кампании в порядке пути (база, сценарий, телефония). Отдельного шага «Проверка» / «Запуск» в мастере нет. После телефонии пользователь оказывается на **Обзоре**, где либо можно запустить, либо видно, почему нельзя.

## 4. Информационная архитектура

### 4.1. Меню клиента

| Пункт | Назначение | Главный вопрос экрана |
|---|---|---|
| **Главная** | Список кампаний. Отдельного пункта «Кампании» нет | Какие кампании есть и что с ними происходит? |
| **Источники** | Файл и подключение по API | Откуда в кампанию попадают записи? |
| **Телефония** | Соединения организации | Какое соединение можно выбрать в кампании? |
| **Аналитика** | Все кампании, фильтр по одной | Что уже произошло по обзвону и сколько это стоило? |
| **Журнал действий** | Действия сотрудников клиента | Кто что изменил, когда и с каким объектом? |

Убрать из клиентского меню:

- Речь и модель
- Библиотека сценариев
- Очередь проверок
- отдельный пункт «Кампании»

### 4.2. Вкладки кампании

**Обзор · База · Сценарий · Телефония · Звонки**

Убрать вкладки: Запуск, Проверка, Отчёт, Настройки.

Настройки не живут отдельным экраном: телефонное — во вкладке «Телефония» кампании, сценарное — во вкладке «Сценарий».

### 4.3. Админ-контур нашей компании (не этот кабинет)

Отдельная поверхность «для нас», в этой спецификации **не проектируется экранами**:

- речь и модель (ключи, распознавание, голос, модель диалога);
- библиотека шаблонов сценария и логика разговора;
- очередь внутренних проверок ограничений.

Клиент эти разделы не видит. Если запуск упирается во внутреннюю неготовность, Обзор говорит об этом человеческим языком и не ведёт в админку.

## 5. Правила входов и кнопок

1. Кампанию открывают **кликом по названию**. Кнопок «Открыть», «Управление», «Отчёт», «Открыть причину» нет.
2. Допустимы **две одинаковые точки** одного действия: в списке и внутри кампании. Подпись и результат совпадают. Третья кнопка туда же запрещена.
3. Главная кнопка отвечает на вопрос «что произойдёт сейчас?». Запрещены: «ОК», «Выполнить», «Подтвердить» без имени действия.
4. Опасное действие называет объект и последствие. Не «Вы уверены?».
5. Primary на экране — одно действие пути. Остальное — обычные кнопки или ссылки в таблице.

Разрешённые пары «список + внутри»:

| Действие | Список (Главная) | Внутри кампании |
|---|---|---|
| Открыть кампанию | клик по названию | — (уже внутри) |
| Приостановить | массовое действие сверху | шапка Обзора |
| Продолжить обзвон | массовое действие сверху, только если это ручная пауза | шапка Обзора, то же условие |
| Остановить | массовое действие сверху | шапка Обзора |
| Запустить | нет | только шапка Обзора, только из черновика / готовности к запуску |

## 6. Экраны

### 6.1. Главная — список кампаний

Колонки (и только они):

| Колонка | Поведение |
|---|---|
| чекбокс строки | выбор для массовых действий |
| название | клик открывает Обзор этой кампании |
| статус | только чтение в строке; смена — массовыми действиями или шапкой Обзора |
| прогресс | `Обзвонили N из M` |

N — число **записей базы**, по которым была хотя бы одна попытка звонка.  
M — число записей, **принятых в базу** этой кампании.  
Не смешивать N с числом соединений, разговоров или обещаний. Не показывать проценты вместо N из M. Если M = 0: `База не загружена`.

Нет колонок «Действия» и «Риск / причина». Причина системной остановки — только в Обзоре.

Над таблицей:

- «Создать кампанию» (главный CTA страницы);
- фильтр статуса;
- массовые действия: «Приостановить кампании», «Продолжить обзвон», «Остановить кампании» — активны, когда выбран хотя бы один подходящий ряд.

Массовое действие применяется только к строкам, для которых оно допустимо. Остальные пропускаются. После выполнения: сколько изменено, сколько пропущено и почему (одной фразой, без внутренних кодов).

Демо-метрики «работают / черновики» над таблицей не нужны: они дублируют список. На Главной один заголовок «Кампании», без второго «Главная» в теле страницы. Крошки не повторяют H1 дословно второй строкой смысла.

Пусто: `Кампаний пока нет. Создайте первую кампанию.`  
Фильтр пуст: `По этому статусу кампаний нет. Сбросьте фильтр.`  
Ошибка загрузки списка: `Не удалось показать кампании. Список не изменился. Обновите страницу.`

### 6.2. Источники

Два рабочих способа:

1. **Загрузка файла** (CSV / XLSX) — как сейчас по смыслу: выбор файла, отчёт «найдено / готовы / исправить / дубли», сопоставление полей, продолжение с принятыми записями. Файл назначается кампании.
2. **Подключить по API** — универсальное подключение без имени вендора CRM. В этой волне это **контракт экрана** (кнопка, короткая форма, статус «подключено / не подключено», что записи будут поступать в выбранную кампанию). Живой обмен и конкретная CRM не выдумываются. Если в репозитории уже есть API обмена — использовать его; иначе остаётся макет.

«Система взыскания» и «защищённая папка» как отдельные обещания «не в этом релизе» с disabled-кнопками не нужны: один вход «Подключить по API» покрывает интеграцию.

Пусто файла: `Файлов пока нет. Загрузите базу или подключите обмен по API.`  
Ошибка файла: что сломалось, что не импортировано, что сделать (формат, обязательные поля).  
API: `Подключение не настроено. Укажите данные обмена, чтобы записи поступали сами.` / `Не удалось сохранить подключение. Данные не отправлены. Проверьте адрес и доступ.`

### 6.3. Телефония организации

Карточки соединений: поставщик (имя компании или «поставщик»), номер, линии, маркировка, статус подключено / не подключено, «Подключить» / «Настроить» / «Проверить соединение».

**Убрать** блок «Проверка готовности телефонии» (чеклист исходящего номера, маркировки, статусов).

Проверка соединения — технический тест линии. Она **не** запускает кампанию и не меняет статус кампании.

Пусто: `Соединений пока нет. Подключите телефонию, чтобы выбрать её в кампании.`

### 6.4. Аналитика

Масштаб по умолчанию — **все кампании** организации. Фильтр: одна кампания или все.

Четыре показателя и только они на первом экране:

| Показатель | Смысл | Знаменатель |
|---|---|---|
| Обзвонено | записи с хотя бы одной попыткой | записи в базе выборки |
| Соединилось | попытки, где было соединение | попытки в выборке |
| Обещания | зафиксированные обещания платежа | завершённые разговоры в выборке. Подпись: «из завершённых разговоров». Не делить на все попытки |
| Стоимость | сумма по событиям учёта | период выборки |

Период выборки всегда виден. Если данные демо или расчёт недоступен — явно «нет данных» / «демо», не живые KPI.

Нет отдельного экрана «Отчёт» в кампании: тот же раздел «Аналитика» с фильтром на эту кампанию. Из Обзора вторая точка входа — ссылка с той же подписью, что пункт меню: «Аналитика». Не «Открыть отчёт» и не «Открыть аналитику».

Пусто: `Пока нечего показать. Цифры появятся после звонков.`  
Ошибка: `Не удалось загрузить аналитику. Цифры не обновлены. Повторите попытку.`

### 6.5. Журнал действий

Только действия **сотрудников клиента**. События системы (запрет звонка, автоостановка движком ограничений) сюда не пишутся.

Колонки строки:

- время (дата и время, 24 часа);
- кто (имя сотрудника);
- объект (кампания и/или должник — человеческие имена, не UUID как заголовок);
- что изменилось (было → стало или формулировка действия);
- IP (только если есть в событии; иначе «не зафиксирован», не выдумывать адрес).

Фильтры: период, сотрудник, кампания. Пагинация обязательна.

Пусто: `Записей пока нет. Здесь появятся действия сотрудников: создание кампании, загрузка базы, запуск, пауза.`  
Нет доступа: `Нет доступа к журналу.` — не маскировать под ошибку загрузки.

### 6.6. Обзор кампании

Главный экран кампании. Отвечает: можно ли запускать или продолжать; сколько обзвонили; что делать дальше.

Шапка (единственное место запуска):

- название;
- статус;
- прогресс `Обзвонили N из M`;
- кнопки по статусу (см. раздел 7).

Тело:

- готовность к запуску **без вкладки «Запуск»**: база, сценарий, телефония — готово / не готово / блокирует. Пункт ведёт на соответствующую вкладку.
- если система остановила кампанию: что произошло, что система уже сделала (новые звонки не создаются), что может сделать менеджер. Без очереди проверок и без «открыть причину» как отдельного раздела.
- краткие цифры как на Аналитике, клик ведёт в Аналитику с фильтром этой кампании.

Логика разговора, ключи речи, внутренние проверки ограничений в Обзоре не показываются формой. Если запуск закрыт внутренней неготовностью: `Запуск сейчас недоступен. Обратитесь к администратору.` — без слов про ключи, модели и внутренние движки.

### 6.7. База кампании

Оставить качество данных, сопоставление, исключения. Разделить:

- принято в базу ≠ разрешено звонить (допуск — перед звонком, не галочка импорта);
- ошибка файла ≠ правило исключения.

Добавить тот же вход, что в «Источниках»: загрузить файл **или** получать записи из подключённого API. Назначить источник этой кампании.

Пусто: `База ещё не загружена. Загрузите файл или подключите обмен по API.`

### 6.8. Сценарий кампании

Клиент настраивает только:

- шаблон;
- голос;
- первую фразу;
- максимальную длительность;
- перевод оператору.

**Скрыть** схему логики разговора (шаги «представиться → проверить личность → …»). Это внутренняя история админ-контура.

Сохранение новой версии — здесь. Критичное изменение сценария на работающей кампании подчиняется backend (блокировка смены на `running`); UI показывает понятный отказ, не обход.

### 6.9. Телефония кампании

Выбранное соединение, исходящий номер, одновременные звонки, маркировка как факт, «Проверить соединение».

Убрать список «что проверяет система». Настройки соединения, которые раньше жили во вкладке «Настройки», переносятся сюда.

Окно времени звонка — не вкладка «Настройки». Его задают при создании кампании и показывают на **Обзоре** в блоке ограничений запуска (будни / выходные). Клиент может только сузить окно; системный минимум из rulebook не выключается. Точные часы минимума в эту спецификацию не записывать — только ссылка на утверждённый rulebook.

### 6.10. Звонки кампании

Таблица шире: меньше сжатых колонок, больше места имени должника и исходу.

Клик по **должнику** (не по отдельной кнопке «карточка») открывает карточку:

- список попыток / разговоров с этим должником (несколько звонков — несколько диалогов);
- выбранный диалог: расшифровка реплик **ИИ-агента** и **человека** по очереди;
- исход попытки и результат разговора раздельно, если оба есть;
- запись: «запись хранится» / «записи нет», без выдуманной ссылки скачивания.

Пусто: `Звонков пока нет. Они появятся после запуска кампании.`  
Нет расшифровки: `Расшифровки этого разговора нет.` — не подменять текстом-заглушкой «как будто был диалог».

## 7. Запуск, пауза, остановка

Backend-статусы не расширять этим документом. Показ в кабинете:

| Код | Клиенту |
|---|---|
| `draft` | черновик |
| `ready` | готова к запуску |
| `running` | работает |
| `auto_paused` | приостановлена системой |
| `completed` | завершена |
| `archived` | в архиве (по умолчанию скрыта в списке) |
| `review` | **не слово review.** Для менеджера это «запуск недоступен» / ожидание внутренней проверки. Раздела «Проверка» нет |

Ручной паузы в enum сейчас нет. В прототипе допускается UI-состояние «приостановлена» (сотрудник). Живой API для него — отдельная backend-задача, не часть этой IA. Не выдавать прототипную ручную паузу за уже существующий статус в БД.

### 7.1. Запустить

- Только шапка Обзора.
- Только когда база, сценарий и телефония собраны.
- Только переход к работе с черновика / готовности (`draft`/`ready` по факту API).
- Перед запуском — подтверждение: что кампания будет ограничено запущена, новые звонки пойдут по правилам продукта.
- Если готовность закрыта (fail-closed): кнопка неактивна, на Обзоре список причин человеческим языком, группировка «блокирует запуск» / «предупреждение». Вкладку «Запуск» не возвращать.
- Тестовая проверка соединения ≠ запуск кампании.

### 7.2. Приостановить

С работающей кампании, с подтверждением: новые звонки не создаются. Точки: массово на Главной и шапка Обзора, одна формулировка «Приостановить кампанию».

### 7.3. Продолжить обзвон

- После **ручной** паузы: те же две точки, одно имя кнопки.
- После **системной** паузы (`auto_paused`): одноразового «Продолжить» в списке нет. Обзор показывает причину (из данных продукта, не код `TIME_WINDOW_…` как заголовок) и что новые звонки не создаются. Возобновление после системной остановки в этой волне **не** отдаётся менеджеру кампаний одним кликом (в API safe-resume — не эта роль). Force-call запрещён. Раздел «Проверка» не создавать.

### 7.4. Остановить

Подтверждение: кампания завершится, для продолжения нужен новый запуск. В UI остановка = переход к «завершена», как уже зафиксировано для stop → `completed`. Не вводить отдельный клиентский статус «остановлена», пока его нет в API.

## 8. Мастер создания

Шаги: кампания (имя, продукт, сегмент, окно времени как сужение системного) → база → сценарий (только поля раздела 6.8) → телефония.  
Кнопка финала: «Создать кампанию» / «Перейти к обзору».  
Шаг «Проверка перед запуском» из мастера убрать: проверка живёт на Обзоре в момент «Запустить кампанию».

Дублировать мастер и вкладки можно: незавершённый черновик открывается во вкладках с того же шага. Подписи шагов совпадают с вкладками.

## 9. Русский язык (та же волна)

Волна включает: словарь, антипаттерны, запрет англицизмов, правила фразы, вычитку **всех видимых** строк клиентского кабинета (включая тосты, пустые состояния, подтверждения, подписи колонок).

### 9.1. Правила фразы

- Современный русский, короткие предложения, сначала итог, потом причина и следующее действие.
- Одно понятие — один термин на всех экранах.
- Глагол в кнопке: создать, загрузить, сохранить, запустить, приостановить, остановить, подключить, выгрузить.
- Тон: спокойный, точный, без рекламы и без обвинения.
- Даты и числа: `12 540`, 24-часовое время, русские формы множественного числа.
- Заголовок экрана не дублирует крошку тем же словом без новой информации.

### 9.2. Антипаттерны (запрещено в кабинете клиента)

- Канцелярит: осуществить, произвести, имеется, является, в рамках, посредством, данный, вышеуказанный, необходимо выполнить.
- Кнопка, которая не называет результат: ОК, Submit, Выполнить, «Подтвердить» без объекта.
- Два заголовка с одним смыслом на одном экране («Главная» + «Главная»).
- Английский код ошибки или HTTP как основной текст.
- «Вы уверены?» без последствий.
- Проценты и абсолюты вперемешку без подписи, что за 100%.
- Слова разработки, архитектуры и внутренних сервисов.
- Обещание функции, которой нет (включенная интеграция «не в этом релизе» как будто она почти работает).

### 9.3. Запрещённые слова в кабинете клиента

Не использовать даже в подсказках:

`compliance`, `QA`, `KPI`, `PTP`, `BYOK`, `ASR`, `TTS`, `LLM`, `sandbox`, `tenant`, `review`, `handoff`.

Замены:

| Нельзя | Нужно |
|---|---|
| compliance | ограничения / звонок не разрешён (по смыслу места) |
| QA | проверка качества — только если экран клиенту нужен; в этой IA отдельного экрана нет |
| KPI | конкретное имя показателя: обзвонено, соединилось, стоимость |
| PTP | обещание платежа |
| handoff | перевод оператору |
| tenant | организация / аккаунт |
| provider / провайдер | поставщик или имя компании (МТС Exolve, Mango Office) |
| review | не показывать клиенту; внутреннее |
| sandbox | не показывать; демо помечать «демо» / «нет данных» |

`API` допустимо только на экране «Источники» в согласованной кнопке «Подключить по API».  
Сложные термины (ключ, модель, распознавание как админская настройка) — только в админ-контуре.

При вычитке обновить `PRODUCT_LANGUAGE.md`: убрать клиентские CTA «Открыть причину» на вкладку «Запуск»; статус речи не отправлять клиента в «интеграции ключей».

## 10. Состояния (минимум на каждый важный экран)

Каждый экран из раздела 6 обязан явно закрывать:

- загрузка;
- данные есть;
- пусто;
- ничего не найдено по фильтру;
- ошибка (операция не выполнена / не известно, выполнена ли — не врать);
- нет доступа;
- действие выполняется;
- действие удалось;
- частичный успех (импорт, массовые действия);
- блокировка запуска на Обзоре;
- системная пауза на Обзоре.

Цвет не единственный носитель статуса.

## 11. Соответствие текущему коду (пробелы)

Эта спецификация меняет IA прототипа. Она **не** добавляет живую CRM, не расширяет enum кампании и не открыет менеджеру safe-resume.

Уже есть и остаётся источником правды, где не противоречит IA:

- статусы Prisma `CampaignStatus`;
- импорт файла и отчёт строк;
- readiness-summary для решения «можно ли запустить» — **показать на Обзоре**, не отдельной вкладкой;
- журнал аудита API — расширить отображение под колонки раздела 6.5; системные события в клиентский журнал не класть, даже если API их отдаёт (фильтр на стороне UI или отдельный параметр, без выдумывания IP).

Разрывы, которые эта IA не закрывает кодом API:

- ручная пауза как отдельный статус;
- IP в аудите, если поля ещё нет;
- универсальный inbound API для базы;
- админ-контур речи и библиотеки сценариев.

Их не имитировать как production-ready.

## 12. Вне скоупа

- Реализация в `prototype.html` до утверждения этого файла и плана.
- `index.html`.
- Экраны админки нашей компании (только граница: клиент их не видит).
- Живой CRM-вендор, webhook-спецификация, новые юридические окна.
- Очередь проверок, вкладки Запуск / Проверка / Отчёт / Настройки.
- Force-call, выключение обязательных ограничений, one-click resume после системной паузы для менеджера.
- Новые метрики аналитики сверх четырёх согласованных.
- Плеер записи и скачивание по вымышленным URL.

## 13. Критерии приёмки дизайна (для следующей реализации)

Клиентский кабинет считается соответствующим этой спецификации, если:

1. Меню и вкладки совпадают с разделами 4.1–4.2, лишнего нет.
2. Путь «создать → база → сценарий → телефония → запустить с Обзора → звонки → аналитика» проходит без тупиков и без третьей кнопки на то же действие.
3. Кампания открывается по названию; колонки Главной — только согласованные.
4. Запуск fail-closed виден на Обзоре; разделов Запуск/Проверка нет.
5. Сценарий без схемы логики; телефония без чеклиста готовности организации.
6. Звонки: несколько диалогов, расшифровка агент / человек.
7. В видимых строках нет запрещённых англицизмов из 9.3.
8. Журнал — только сотрудники клиента, поля как в 6.5.
