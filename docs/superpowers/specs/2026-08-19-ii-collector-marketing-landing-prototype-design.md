# Дизайн: маркетинговый лендинг “ИИ-коллектор” (статический прототип)

## Дата
2026-08-19

## Контекст и цель
Нужен рабочий прототип маркетингового лендинга “ИИ-коллектор”, который открывается напрямую в браузере как статическая страница.

Точка входа: корневой `index.html` (страницу необходимо полностью заменить на новый лендинг “с нуля”).

Цель конверсии: действие “Назначить демо”.

### Ограничения
- Не трогать `prototype.html`.
- Без внешних UI-фреймворков.
- Форма заявки работает в странице (lead-relay при наличии URL; иначе локальный success).
- Кнопка CTA: текст **строго** “Назначить демо” (одинаковый во всех местах).
- Русский язык естественный, без англицизмов в местах, где есть русский смысл.
- Запрещены AI-градиенты/glow/glassmorphism как основа визуала.

## Пользовательское поведение (conversion flow)

**Канон GitHub Pages (`public/index.html`), путь A — inline-форма (2026-08-20):**

1. Пользователь читает лендинг.
2. Пользователь нажимает “Назначить демо” (header / mid-page / финально / sticky) или сразу видит форму в hero.
3. Якорь ведёт к `#demo-form` (inline-форма в hero, без модалки).
4. Пользователь заполняет поля и нажимает “Отправить заявку”.
5. Показывается сообщение: **“Спасибо, мы свяжемся с вами в ближайшее время.”**

Модальный путь B (`role="dialog"`, Esc, overlay) **не используется** на Pages без отдельного A/B; не возвращать без явной задачи.

## Ключевые сущности UI
### CTA “Назначить демо”
- Одна и та же кнопка/лейбл во всех местах:
  - header / hero (якорь на `#demo-form`);
  - 1–2 раза по ходу чтения в ключевых секциях;
  - финальный CTA-блок;
  - sticky CTA.

### Sticky CTA
- Реализация: “dock”-подобная фиксированная кнопка внизу экрана.
- Требование: **не перекрывать контент** и корректно работать на mobile.
- Техническое следствие для верстки: основной контейнер/`body` должен иметь `padding-bottom`, равный высоте sticky CTA (`--sticky-height`), чтобы последний контентный блок не уходил под неё.

### Форма “Назначить демо” (inline `#demo-form`)
Поля (минимум 3, по одобренному варианту — 4):
- Имя
- Компания
- Email
- Телефон

Кнопка:
- “Отправить заявку”

Состояние после отправки:
- Inline success-message в карточке формы: **“Спасибо, мы свяжемся с вами в ближайшее время.”**

Рядом с полями — короткий список ожиданий от демо (проверки / специалист / журнал), без обещания обзвона боевой базы клиента.

## Структура лендинга (обязательные секции)
Страница должна быть цельной, логичной и современной (B2B-лендинг, не шаблон “AI-лендинг”).

### 1) Hero (главный экран)
Состав:
- Заголовок (строго по делу)
- Короткое под-сообщение
- Главный CTA-кнопка: “Назначить демо”
- Небольшие факт-тезисы (управляемость/проверка/передача специалисту/журнал действий)

### 2) “Как это работает”
5–8 коротких шагов (вариант: 7 шагов):
1. Подключаем сценарий и контекст пилота
2. Проверка ограничений перед действиями
3. Готовим допустимые контакты и расписание
4. Ведём управляемый диалог
5. Выделяем спорные ситуации для проверки
6. Передаём специалисту, где нужно
7. Показываем результат и журнал действий

### 3) “Почему нам можно доверять”
3–4 пункта “управляемость/контроль/прозрачность” без драматизации:
- Понятные причины решений
- Контроль процесса
- Журнал действий по фактам
- Предсказуемый пилот (ограниченный и ориентированный на готовность)

CTA:
- Кнопка “Назначить демо” в конце секции (второй ключевой повтор).

### 4) “Преимущества”
2–4 доказательных пункта (вариант: 4):
1. Проверка ограничений перед действиями
2. Передача специалисту там, где нужна проверка
3. Журнал действий по фактам
4. Ограниченный пилот вместо обещаний “сразу в масштаб”

### 5) “Кому подходит”
Минимум 3 роли/сценария (вариант: 4):
- Руководитель взыскания / операционный руководитель
- Юристы и руководители по рискам
- Супервизор / очередь специалистов (контроль качества)
- Администратор интеграций

CTA:
- Кнопка “Назначить демо” после блока (или в его нижней части) как следующий ключевой повтор.

### 6) FAQ
5–7 вопросов (вариант: 6) с короткими ответами без обещаний “волшебных” эффектов:
1. Что будет на демо?
2. Как принимаются решения разрешено/требуется проверка?
3. Что происходит при спорных ситуациях/риске?
4. Можно ли остановить пилот?
5. Какие результаты показываете?
6. Кому подходит по ролям/процессу?

### 7) Финальный CTA-блок
Заголовок + короткий текст и финальная CTA-кнопка “Назначить демо”.

## Визуальный стиль (enterprise/B2B)
### Общие принципы
- Спокойная сетка, аккуратная типографика, чёткая иерархия.
- Спокойные нейтральные цвета, один основной акцент (например, сине-зелёный/синий).
- Нет AI-градиентов, glow, glassmorphism.
- Без “Lorem ipsum”.

### CSS-токены
Стилевую часть построить на `CSS variables` в `:root`:
- цвета (основной текст, мутный текст, линии, фон, акцент, danger/warn при необходимости),
- типографика (семейство, масштабы заголовков),
- spacing (gap, padding, max-width контейнера),
- радиусы (если используются) и shadow (минимальные).

## Компоненты (минимальный набор)
- Primary button: “Назначить демо”
- Secondary text-link (например, “Как устроен продукт”) — визуально слабее primary
- Inline demo form `#demo-form` + success state (не модалка)
- FAQ accordion: через `details/summary` или минимальный JS-аккордеон (доступность обязательна)

## Доступность и UX-требования
- Все кнопки CTA доступны по `Tab`; порядок: header CTA → поля формы.
- Sticky CTA:
  - видима и кликабельна на mobile,
  - скрыта на desktop (`min-width: 761px`),
  - не перекрывает контент (через `padding-bottom` / `--sticky-height`),
  - лейбл кнопки = “Назначить демо”.

## Самопроверка spec (без TBD)
- Все обязательные секции присутствуют.
- CTA “Назначить демо” в header/hero, по ходу чтения, sticky, финально — предусмотрены.
- Inline-форма с полями: имя/компания/email/телефон и кнопкой “Отправить заявку” + success-сообщение.
- Запрещённые визуальные эффекты не планируются.
- Русские формулировки опираются на терминологию: “проверка ограничений”, “передача специалисту”, “журнал действий”.
