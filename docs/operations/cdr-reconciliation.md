# Сверка CDR (пилот)

Документ описывает ручной процесс сверки статусов поставщика телефонии с `CallAttempt` на controlled pilot. Это не production cron и не автоматическое удаление данных.

## Когда запускать

- После тестового или sandbox-обзвона, если статусы в кабинете и у поставщика расходятся.
- Перед разбором инцидента «звонок был, в журнале нет» или наоборот.

## Что сравниваем

- Идентификатор вызова поставщика (`providerCallId`).
- Статус у поставщика vs статус `CallAttempt`.

Модуль `src/telephony/cdr-reconciliation.ts` работает на in-memory/fake записях. HTTP к поставщику не вызывается.

## Что делать при mismatch

1. Зафиксировать событие аудита-заглушку `cdr.mismatch` (без удаления попытки или записи).
2. Разобрать вручную: повторный запрос статуса, проверка записи разговора, журнал кампании.
3. Не удалять `CallAttempt` и не «выравнивать» статус автоматически.

## Ограничения пилота

- Нет расписания, нет очереди Redis, нет авто-ретрая.
- Live HTTP к Exolve/Mango не используется.
