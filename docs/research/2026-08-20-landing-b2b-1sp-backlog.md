## Правила

- За проход — **одна** задача `todo`.
- CTA везде строго: **«Назначить демо»** (лейбл кнопки; якорь может вести к `#demo-form`).
- Не обещать полностью автономное взыскание.
- Не трогать `prototype.html` / кабинет.
- Не копировать чужие бренды — только паттерны.
- Anti-patterns (запрещено в любой задаче): purple/indigo glow, glass как основа, emoji, pill-clusters «GPT/Agentic», Midjourney-абстракции, «магический ИИ», два равноправных главных CTA в hero.

## Дизайн (`LD-*`)

### LD-01: Hero VP «управляемый пилот», не «голосовой бот»

Статус: `done`

Контекст для следующих задач:

- Hero `h1`: «ИИ-коллектор: управляемый пилот телефонного взыскания» (53 символа, бренд в заголовке).
- Lead явно снимает полную автономию («не полностью автономное взыскание») и держит канон: проверка ограничений / специалист / журнал.
- Primary CTA без изменений по смыслу: header + форма `#demo-form` («Назначить демо»). Secondary «Как устроен продукт» ослаблен (`.hero-link`: muted, 14px, underline; без стрелки) — не конкурирует с CTA.
- Не трогали `.value-strip`, шаги `#how-it-works`, trust `#control`, сегменты, форму, шрифты/фон (это `LD-02`…`LD-07`).
- `tests/public-landing.test.ts` зелёный без правок; `LT-01` всё ещё может ужесточить контракт под новый VP (управляемый пилот / anti-autonomy).
- Риск регрессии: не возвращать accent+bold на `.hero-link`; не укорачивать `h1` до «голосовой бот»-формулировок; не обещать полную автономию в lead.

Что сделать:

- Переписать `h1` + `hero-lead` так, чтобы за 5 секунд было ясно: управляемая автоматизация телефонного взыскания с проверками и передачей специалисту.
- Явно снять ожидание полной автономии (одна короткая фраза в lead или рядом).
- Бренд «ИИ-коллектор» оставить hero-level сигналом (не прятать в eyebrow).
- Оставить один главный CTA-якорь на `#demo-form` («Назначить демо»). Ссылку «Как устроен продукт» не конкурировать по визуальному весу с CTA.

Где менять:

- `public/index.html` (блок `.hero`)

Критерии готовности:

- Заголовок ≤ 72 символа (как в текущем тесте).
- Нет слов «магия», «автономно взыщет», «без оператора полностью».
- Лид содержит проверку / специалиста / журнал (или эквивалент из словаря).

### LD-02: Разгрузить первый экран (hero budget)

Статус: `done`

Контекст для следующих задач:

- В `.hero` остались: eyebrow, h1, lead, строка `.hero-points` («Проверки · специалист · журнал»), secondary-link, форма. Карточной сетки в hero нет.
- `.value-strip` вынесен в отдельную секцию `.value-band` сразу после hero (ниже fold на desktop) — mid-page value, не дашборд первого экрана.
- Не трогали `#how-it-works` (`LD-03`), trust (`LD-04`), роли (`LD-05`), форму copy (`LD-06`).
- Тесты зелёные без правок; hero-селектор в тесте больше не видит `.value-strip` внутри `<section class="hero">`.
- Риск: не возвращать `.value-strip` внутрь `.hero`; не раздувать `.hero-points` в pill-cluster.

Паттерн: Скорозвон / Symend — 3 тезиса max; не дашборд в hero.

Что сделать:

- Убрать или вынести ниже fold полосу `.value-strip` из первого viewport (сейчас 3 карточки конкурируют с формой).
- В hero оставить: бренд, headline, 1 lead, форма/CTA, максимум 3 коротких тезиса **без карточной сетки** (например, одна строка буллетов: проверки · специалист · журнал).
- Не добавлять стат-ленту и pill-кластеры.

Где менять:

- `public/index.html` (`.hero`, `.value-strip`)

Критерии готовности:

- На типичном desktop 1440×900 ключевой VP + форма читаются без скролла карточной полосы.
- Карточки value-strip не стоят внутри первого экрана как «дашборд».

### LD-03: Переупорядочить «Как это работает» под реальный контур

Статус: `done`

Контекст для следующих задач:

- 7 шагов в `#how-it-works`: сценарий пилота → проверка ограничений → контакты/расписание → управляемый диалог → спорные ситуации → специалист → результат/журнал.
- Проверки стоят **до** диалога/обзвона (шаг 02).
- Убраны CSV/XLSX и «исходящий контур»; тон для ЛПР.
- Не трогали `#control` (`LD-04`), `#roles` (`LD-05`), форму (`LD-06`).
- Риск: не возвращать проверки после запуска обзвона; не тащить кабинетный жаргон в подписи шагов.

Паттерн: IQDialer 4 шага / Symend 5 steps; спека 7 шагов.

Что сделать:

- Исправить порядок шагов: **проверки до обзвона**, не после запуска.
- Канон (человеческим языком, словарь продукта):
  1. Подключаем сценарий и контекст пилота  
  2. Проверка ограничений перед действиями  
  3. Готовим допустимые контакты и расписание  
  4. Ведём управляемый диалог  
  5. Выделяем спорные ситуации  
  6. Передаём специалисту  
  7. Результат и журнал действий  
- Убрать кабинетный жаргон («CSV/XLSX», «исходящий контур») из маркетинговых подписей — заменить на смысл для ЛПР.
- Одна мысль на шаг; без техноаббревиатур.

Где менять:

- `public/index.html` (`#how-it-works`)

Критерии готовности:

- Шаг про ограничения идёт **до** шага обзвона/диалога.
- 5–7 шагов, сканируются за ~10 секунд.

### LD-04: Trust-блок без истерики и без «AI magic»

Статус: `done`

Контекст для следующих задач:

- `#control`: 4 процедуры — проверка до звонка · передача специалисту · журнал · ограниченный пилот; сетка 2×2.
- Lead спокойный ops («процедуры встроены»), без «безопасности как отдельного продукта» в истеричном тоне.
- Заголовок «Контроль — часть процесса…» сохранён (контракт теста).
- Не трогали `#roles` (`LD-05`), форму (`LD-06`), benefits (`LD-10`).
- Риск: не добавлять фейковые %; фраза «ограниченный пилот» уже 1× — лимит теста ≤2.

Паттерн: TrueAccord / Диадок / Infinity — процедуры > прилагательные.

Что сделать:

- Секцию `#control` (или переименовать заголовок) сделать trust-ядром: проверки до звонка · передача специалисту · журнал действий · ограниченный пилот.
- Убрать формулировки вроде отдельного «контура безопасности» как маркетинговый трюк, если они звучат защитно-истерично; тон — спокойный ops.
- Не добавлять фейковые % «+300%» без кейса.

Где менять:

- `public/index.html` (`#control`, при необходимости `#benefits`)

Критерии готовности:

- 3–4 пункта trust, каждый с одной конкретной процедурой.
- Нет «магии ИИ» и пустых суперлативов.

### LD-05: «Кому подходит» — сегменты рынка + роли

Статус: `done`

Контекст для следующих задач:

- `#roles`: сначала 4 сегмента (банки / МФО / ПКО / КЦ взыскания), затем вторичный ряд ролей + CTA «Назначить демо».
- Lead явно: не массовый self-serve и не для частных лиц.
- Селекторы: `.segments-grid`, `.roles-secondary`, `.roles-secondary-lead`.
- Не трогали форму (`LD-06`) и финальный CTA (`LD-09`).
- Риск: не заменить сегменты снова только ролями; не убирать CTA после блока.

Паттерн: LuxBase / MightyCall — сегменты; спека — роли.

Что сделать:

- Пересобрать `#roles`: сначала **сегменты** (банки / МФО / ПКО / КЦ взыскания) — по одной фразе сценария.
- Роли (руководитель взыскания, риск/юристы, супервизор, интеграции) — вторичным рядом или короткими подписями, не вместо сегментов.
- После блока — повтор CTA «Назначить демо».

Где менять:

- `public/index.html` (`#roles`)

Критерии готовности:

- Видны минимум 3 сегмента рынка.
- Понятно, что продукт не consumer и не self-serve «для всех».

### LD-06: Ожидания от демо рядом с формой

Статус: `done`

Контекст для следующих задач:

- В `.hero-form-card`: intro + `.demo-expect` (3 пункта: проверки / специалист / журнал); явно «без обзвона вашей боевой базы».
- Не использована запрещённая тестом фраза «Что покажем на демо» — список без этого заголовка.
- Сабмит: «Отправить заявку»; поля без изменений.
- `LT-01` может заменить запрет фразы на контракт наличия `.demo-expect` + anti-magic.
- `LT-02`: путь A (inline `#demo-form`) подтверждён этой волной.
- Риск: не вернуть общий «на вашем примере» без пунктов; не обещать live-обзвон боевой базы.

Паттерн: Catchpole «what you'll see»; FAQ уже частично есть.

Что сделать:

- В карточке формы `#demo-form` заменить общий текст на конкретный список из 3 пунктов: что покажем на демо (проверки, эскалация специалисту, журнал) — **без** запрещённой тестом дословной фразы, если тест ещё держит запрет: согласовать с `LT-02`.
- Кнопку сабмита оставить ясной («Отправить» / «Отправить заявку»); не плодить второй главный CTA.
- Не обещать live-обзвон реальной базы клиента на первом демо.

Где менять:

- `public/index.html` (`.hero-form-card`)
- при необходимости `tests/public-landing.test.ts` (`LT-02`)

Критерии готовности:

- Рядом с полями видно, **что** будет на демо.
- Поля: имя, компания, email, телефон — без лишних полей.

### LD-07: Визуальный язык B2B fintech/ops (anti AI-landing)

Статус: `done`

Контекст для следующих задач:

- Шрифты: IBM Plex Sans + IBM Plex Serif (Google Fonts); `--font` / `--font-display`.
- Палитра: холодный slate/steel blue ops; hero-фон с лёгким radial без glow/glass.
- Шапка: solid `#f7f9fb`, **без** `backdrop-filter`.
- Карточки mid-page сохранены; hero без карточного дашборда (после `LD-02`).
- Не трогали motion (`LD-08`), sticky label (`LD-09`).
- Риск: не вернуть Inter/system-first и glass blur в header.

Паттерн: Диадок / Naumen / Infinity; anti-patterns research §4.

Что сделать:

- Заменить стек `Inter` / system на выразительный, но деловой (например, пара: display + text через Google Fonts или self-host) — без «AI startup» гротеска.
- Усилить CSS-переменные: убрать ощущение шаблонного SaaS-серого, если нужно — лёгкий градиент/паттерн фона **без** glow и glass.
- Убрать `backdrop-filter: blur` у шапки, если он читается как glassmorphism.
- Карточки: оставить только там, где помогают сканированию mid-page; hero без «карточного дашборда».

Где менять:

- `public/index.html` (`:root`, typography, header, surfaces)

Критерии готовности:

- Нет purple/indigo glow, glass-hero, emoji.
- Бренд и акцент узнаваемы без Midjourney-фона.
- Desktop + mobile читаемы.

## Чеклист anti-patterns (для `LD-09`)

- [ ] Нет purple/indigo glow / glass / orbs  
- [ ] Нет emoji в заголовках и trust  
- [ ] Нет pill-clusters GPT/Agentic/Realtime  
- [ ] Нет обещания «ИИ сам взыщет»
