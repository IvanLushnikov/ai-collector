# UX/UI-аудит кабинета ИИ-коллектора

Дата: 17.08.2026  
Статус: improve existing, not invent  
Объект аудита: `prototype.html` (рабочий кабинет)  
Связанный CJM: `index.html` (не кабинет пользователя)  
Режим: разобрать текущий дизайн, найти разрывы пути, предложить точечные доработки. Код и экраны не менялись.

Источники истины: [prd-draft.md](prd-draft.md), [prd-open-questions.md](prd-open-questions.md) §6–7, [rulebook-v1.md](../compliance/rulebook-v1.md), `PRODUCT_LANGUAGE.md`, `ROADMAP_B2B_SAAS.md`, `TECH_BACKLOG_1SP.md`, readiness/calls/review API, доменные статусы кампании и исходов.

Юридические лимиты, частота контакта, время звонка, stop-conditions, retention и outcome taxonomy в этом файле не выдумываются. Если факта нет в продукте — помечено «нужно confirm».

## A. Короткий диагноз

Рабочий каркас кабинета уже есть: мастер из пяти шагов, карточка кампании с вкладками, readiness на запуске, чеклист safe-resume после автопаузы, журнал звонков с карточкой, вкладка «Проверка» и отчёт с drill-down. Главный разрыв пути в другом: **оператор не видит риск там, где принимает решение**. На «Главной» и в списке кампаний стоят демо-KPI как факты, автопауза прячется за «Перенастроить», глобальная «Очередь проверок» пустая, тестовый звонок переводит кампанию в «работает», а «Подтвердить» в review снимает паузу без чеклиста. Контроль есть внутри вкладок, но вход в работу ведёт мимо него.

## B. CJM as-is vs to-be

Не новый путь. Канонические этапы кабинета и CJM звонка из `index.html`, связанные с тем, что должен увидеть менеджер / QA / compliance в тот же момент.

| Этап | Как сейчас в prototype / index | Что ломается | Точечная доработка |
|---|---|---|---|
| Создание кампании | Мастер 1–5 есть, черновик сохраняется | Ошибки API не обязательны для «Далее»; статусы UI (`manual_paused`, `stopped`) не совпадают с API (`draft/review/ready/running/auto_paused/completed/archived`) | На шаге 1 показывать ответ API; статус в шапке брать из модели кампании, не из локального lifecycle |
| Импорт | Dropzone, «Загрузить пример», маппинг 4 полей, на «Базе» 10 000 / 8 740 / 1 260 | Пример выглядит как успешный импорт; нет `timezone`, `debtStatus`, `consentStatus`; «исключено» смешивает правила и ошибки; API-ошибки на английском | Показать найденные / готовые / требуют исправления / дубли; привязать к сущности загрузки; русские `message` + next step |
| Качество данных | Метрики на вкладке «База», статус «проверено» | Нельзя скачать проблемные строки; «допущено» читается как eligibility, хотя это ещё не проверка перед звонком | Разделить «принято в базу» и «допущено к звонку»; ссылка на строки с ошибками |
| Настройки | Вкладка «Настройки» + сценарий/телефония | Окно звонка — свободный текст; нет пометки системного минимума; «Лимиты и время = Применены» всегда зелёные | Поля окна только сужение; lock-правила не выключаемые; лимиты — отдельный пункт readiness из API |
| Readiness | Чеклист в мастере и на «Запуске»; overview подменяется API после JS | Первый кадр overview — четыре зелёные галочки; блокирующие и предупреждения в одной куче; `stale` мапится в стиль автопаузы | Группы «Блокирует запуск» / «Предупреждение»; кнопка запуска `disabled`; не показывать зелёный HTML до ответа API |
| Controlled launch | Кнопка «Запустить тестовый обзвон» | Нет модалки объёма/режима; тестовый звонок ставит `running`; live vs sandbox не разделены | Тест ≠ запуск; подтверждение: кампания, режим, cap если есть, что будет при риске |
| Звонки | Журнал + drawer; fallback «демо» | Исход `transferred` вместо API `handoff`; в демо-решении есть `review_required`, в API только `allow/block`; верификация не поле | Колонки: статус попытки, исход, решение, QA; в карточке — identity gate отдельно |
| Риски | Safe-resume на «Запуске»; в шапке «Возобновить после проверки» | На списке/главной риска нет; «Кампания в рабочем режиме. Риск-событий нет.» — дефолт; approve в review снимает автопаузу | Баннер риска выше KPI; resume только через чеклист; review не меняет статус кампании сам |
| Review / handoff | Вкладка кампании рабочая; CJM в `index.html` описывает transfer | Глобальный пункт меню — заглушка; drill-down отчёта открывает её; типы `legal_review` / `manual_override` выдуманы | Собрать существующую таблицу+drawer на глобальном экране; типы только из review API |
| Результаты / отчёт / журнал | Отчёт с ролями и drill-down; журнал действий тянет API с fallback | Главная показывает 3 084 / 1 172 как факт; «Завершено» в воронке сверлит `outcome=all`; роль в отчёте переключается селектом | KPI только из API или с меткой «демо»; воронка с понятным знаменателем; роль — из доступа, не impersonation |
| Eligibility (CJM звонка) | index: timezone / limits / opt-out; кабинет: решение в карточке | Менеджер не видит «почему не звонили» в списке без открытия; коды `TIME_WINDOW_VIOLATION` ≠ `CALL_WINDOW_BLOCK` | В журнале: итог + человекочитаемая причина + время решения |
| Дозвон | index: маркировка; кабинет: статус попытки частично | Нет явного «маркировка на этом звонке»; sandbox выглядит как live при падении API | Бейдж источника `live` / `демо` на строке, не только над таблицей |
| Верификация | Есть в сценарии и тестовом диалоге | В карточке звонка нет поля identity; демо-транскрипт: «я представитель банка» | Поле «личность: подтверждена / не подтверждена / третье лицо» до суммы долга |
| Диалог | Расшифровка в drawer; прослушивание в v1 не входит | Ссылка «Скачать запись» при `sandbox://…`; timeline сырой (`stage`, `usage-event`) | Транскрипт + outcome; запись — «хранится / нет», без плеера; техсобытия свёрнуты |
| Исход | PTP / перевод / нет ответа / блок | Смешаны telephony status и business outcome; нет `dispute`, `callback_requested` | Две строки: соединение и результат разговора из enum API |
| Follow-up | index: подтверждение канала; rulebook: постзвонок — legal-confirm | В кабинете нет следующего шага оператора; review nextStep предлагает «снять автопаузу» | Для PTP: сумма/дата + «ожидает человека, если нужен»; без SMS/email. Для handoff: задача в очереди |

## C. Находки

Формат: проблема → где сейчас → риск/последствие → конкретная доработка существующего UI → роль → приоритет.

### Критично

1. **Проблема:** на входе в кабинет риск слабее демо-KPI, а действие при автопаузе — «Перенастроить».  
**Где:** `Главная` (3 084 диалога / 1 172 обещания), список кампаний (фильтр только «Работает / Черновик»), вторичная кнопка у «Просрочка 8–30 дней».  
**Риск:** supervisor принимает «кампания успешна» или идёт в настройки вместо разбора остановки.  
**Доработка:** в обеих таблицах колонка риска/причины рядом со статусом; при `автопауза` главный CTA — «Открыть причину» → вкладка «Запуск» с баннером; KPI на главной либо из API, либо явная метка «демо», иначе не показывать.  
**Роль:** supervisor, collection_manager.  
**Приоритет:** критично.

2. **Проблема:** точка входа QA/compliance сломана.  
**Где:** экран `#reviewQueue` — заголовок и абзац без таблицы; `renderReviewQueue()` пишет в `#reviewQueueBody` на вкладке кампании; drill-down отчёта вызывает `showScreen('reviewQueue')`.  
**Риск:** спорные звонки не разбираются; кажется, что очереди нет.  
**Доработка:** перенести существующую таблицу, фильтры, метрики и `reviewDrawer` на глобальный экран; из кампании оставить ту же таблицу, отфильтрованную по `campaignId`. Не плодить второй UI.  
**Роль:** qa_analyst, compliance_officer.  
**Приоритет:** критично.  
**Нужен API/поле:** список review-items уже описан в `docs/review-items-api.md`; пока UI на локальном массиве.

3. **Проблема:** тестовый звонок = запуск кампании.  
**Где:** `#runTestCall` → `setCampaignState('running')`; `#launchCampaign` без модалки объёма/режима, только toast «Кампания запущена».  
**Риск:** sandbox-проверка выглядит как боевой обзвон; нет фиксации, что именно запускается.  
**Доработка:** тест меняет только блок «Тестовый звонок» (номер, итог, время). Запуск — отдельное подтверждение: название, `readinessState`, sandbox/live, cap если есть в данных, «новые звонки начнутся / при риске — автопауза». Кнопка «Запустить тестовый обзвон» disabled, пока не `ready`.  
**Роль:** collection_manager.  
**Приоритет:** критично.  
**Нужен API/поле:** переход статуса кампании + audit event (уже в бэклоге launch).

4. **Проблема:** решение в review само снимает защитную остановку.  
**Где:** `updateReviewDecision`: `approved` → `running`, `escalated` → `auto_paused`; источник `manual_override`; nextStep RQ-1001: «Снять автоматическую паузу…».  
**Риск:** one-click resume в обход safe-resume; создаётся впечатление override.  
**Доработка:** кнопки review только меняют статус задачи (`approved/rejected/escalate/requeue`) и пишут audit. Возобновление кампании — только чеклист на «Запуске». Убрать `manual_override` из UI.  
**Роль:** compliance_officer (решение), collection_manager (запуск после разрешения).  
**Приоритет:** критично.

5. **Проблема:** системные ограничения выглядят уже выполненными или настраиваемыми как обычные поля.  
**Где:** чеклист «Лимиты и время / Применены» в мастере и на «Запуске»; «Настройки» — свободный ввод «Будни / Выходные»; первый HTML overview — четыре `✓`.  
**Риск:** запуск при непроверённых лимитах; видимость, что окно можно расширить; ложный «готов» до API.  
**Доработка:** лимиты — пункт readiness из API (`reasonText` + `nextAction`), не захардкоженный green. Окно звонка: только сужение, системный минимум read-only. Overview не рендерить зелёные строки до `readiness-summary`.  
**Роль:** collection_manager.  
**Приоритет:** критично.  
**Нужен API/поле:** `reasons[].reasonCode/reasonText/nextAction` уже в readiness-summary; отдельного «можно ли расширить окно» в API нет — не делать шире минимума в UI.

### Важно

6. **Проблема:** импорт не даёт решить «можно ли идти дальше с частью базы».  
**Где:** шаг 2 мастера, вкладка «База».  
**Риск:** частичный успех = полный успех; обязательные поля API скрыты.  
**Доработка:** отчёт: найдено N, готовы, требуют исправления, дубли; список причин по строкам; «продолжить с валидными» vs «исправить файл». В маппинге показать поля API: номер клиента, телефон, часовой пояс, сумма, статус долга, статус согласия.  
**Роль:** collection_manager.  
**Нужен API/поле:** контракт импорта есть; русские `message` в `src/import/*` ещё английские.

7. **Проблема:** карточка звонка не доказывает цепочку CJM.  
**Где:** `#callCardDrawer`; демо `call-883090` («я представитель банка»); колонка «Источник исхода».  
**Риск:** нельзя проверить disclosure, identity, решение и исход раздельно; QA учится на запрещённой формулировке.  
**Доработка:** сверху: статус попытки | исход из API | решение allow/block + причина + время | QA. Отдельная строка «личность». Транскрипт без нарушения представления. Техтаймлайн свёрнут. Исходы: `handoff`, не `transferred`.  
**Роль:** qa_analyst, compliance_officer.

8. **Проблема:** «Источники» показывают вне-v1 интеграции как готовые.  
**Где:** карточка «Система взыскания · подключена», «Защищённая папка»; в сценариях кнопка «Прослушать».  
**Риск:** обещание обратной выгрузки/обмена и прослушивания, которых нет в v1.  
**Доработка:** оставить загрузку файла как рабочий путь; обмен и папку пометить «не в этом релизе» без статуса «подключена». «Прослушать» убрать или заменить на «Тестовый диалог» (drawer уже есть).  
**Роль:** collection_manager, integration_admin.

9. **Проблема:** экраны «Телефония» и «Сценарии» есть, но их нет в сайдбаре.  
**Где:** `#telephony`, `#scripts` vs nav: Главная / Кампании / Источники / Очередь / Журнал. IA в PRD: Интеграции и Сценарии на верхнем уровне.  
**Риск:** integration_admin не входит в свою работу; дубли с вкладками кампании без входа.  
**Доработка:** не новая IA — показать уже существующие экраны в nav (или один пункт «Интеграции», внутри: источники + телефония). Вкладки кампании оставить выбором соединения/версии.  
**Роль:** integration_admin.

10. **Проблема:** pause/stop без подтверждения с последствиями.  
**Где:** `#pauseCampaign`, `#stopCampaign` — сразу toast.  
**Риск:** окончательная остановка неотличима от паузы; нет audit-смысла для пользователя.  
**Доработка:** модалки по уже существующему тону: «Приостановить …? Новые звонки не создаются.» / «Остановить …? Для продолжения нужен новый запуск.» Кнопки называют действие. Статус `stopped` в API нет — **нужно confirm**, что UI-«остановлена» = `completed` или отдельный переход.  
**Роль:** collection_manager, supervisor.

### Улучшение

11. **Проблема:** тексты и бейджи смешивают внутренние имена с пользовательскими.  
**Где:** селект «Compliance officer»; activity `campaign state: …`; `safe-resume`; `callAttemptId=` в карточке; «Источник исхода».  
**Доработка:** «Специалист по ограничениям»; «Кампания приостановлена системой»; идентификаторы — вторым уровнем.  
**Роль:** все роли кабинета.

12. **Проблема:** селект роли в отчёте имитирует смену должности.  
**Где:** `#reportRoleSelector`.  
**Доработка:** показывать секции по реальной роли; селект убрать или оставить как «что видит роль» только в демо с явной подписью «демонстрация прав».  
**Роль:** все.

## D. Очередь доработок

Порядок внедрения: один заход закрывает один разрыв пути.

1. **Главная + список кампаний.** Статус и риск слева, демо-KPI не как факт, CTA автопаузы → «Запуск». Зачем: починить вход. API: желателен список кампаний со статусом; до него — честно разметить демо.
2. **Глобальная очередь проверок.** Вставить существующую таблицу/drawer на `#reviewQueue`. Зачем: QA/compliance могут начать работу. API: подключить review-items, когда готово; вёрстка не ждёт API.
3. **Тест ≠ запуск.** Убрать `running` у `#runTestCall`; модалка запуска. Зачем: не выдать sandbox за обзвон. API: status transition + audit на подтверждении.
4. **Review не возобновляет кампанию.** Зачем: закрыть обход safe-resume. API: resolve review-item без смены `campaign.status`, если контракт так устроен — **нужно сверить** `docs/review-items-api.md`.
5. **Readiness: блокирует / предупреждение.** Overview без ложных `✓`; лимиты не «всегда применены». Зачем: кнопка запуска = факт API. API: уже `readiness-summary`.
6. **Импорт: качество + поля + русский next step.** Зачем: решить, идти ли с частью базы. API: да, плюс русские сообщения валидатора.
7. **Карточка звонка под CJM и enum API.** Зачем: доказать действие. API: calls detail уже есть; identity-поле — **если нет в API, не выдумывать**, показать только транскрипт + «нужно confirm».
8. **Источники/сценарии: убрать ложную готовность интеграций и «Прослушать».** Зачем: не обещать v1-out. API: нет.
9. **Подтверждения паузы/остановки + статусы = backend enum.** Зачем: destructive не в toast. API: да для stop/complete.
10. **Проход текстов** по таблице E. Зачем: один словарь. API: нет.

## E. Тексты, которые надо поменять

Термины только из `PRODUCT_LANGUAGE.md`.

| Было | Стало | Почему |
|---|---|---|
| Перенастроить (у кампании в автопаузе) | Открыть причину | Действие должно вести к риску, не к форме |

| Прослушать | Тестовый диалог | Прослушивание аудио вне v1 |
| Compliance officer | Специалист по ограничениям | `PRODUCT_LANGUAGE.md` |

| Передача оператору (фильтр `transferred`) | Перевод оператору (`handoff`) | Словарь + API |
| Я представитель банка. (демо-транскрипт) | Я автоматизированный интеллектуальный агент … от имени … | Disclosure из rulebook / сценария |
| Снять автоматическую паузу после устранения нарушения… | Проверьте событие. Возобновление — на вкладке «Запуск» после чеклиста | Нет force-resume из review |
| Подтвердить (в review, если читается как запуск) | Подтвердить разбор / Оставить в очереди / Передать дальше | Не возобновлять кампанию |
| Вы уверены? — в UI сейчас нет; pause/stop идут без диалога | Приостановить «…»? Новые звонки не создаются. / Остановить «…»? Для продолжения нужен новый запуск. | Destructive с последствиями |
| Missing required columns: timezone… (если API ошибка всплывёт в UI) | Не удалось загрузить базу. Добавьте столбцы: часовой пояс, сумма долга, статус долга, статус согласия. | Copy skill + реальные поля импорта |

## F. Что не трогать

- Имя продукта «ИИ-коллектор», организация в шапке.
- Мастер из пяти шагов и вкладки кампании Обзор / База / Сценарий / Телефония / Запуск / Звонки / Проверка / Отчёт / Настройки — чинить содержимое, не пересобирать IA.
- Чеклист safe-resume (причина, закрытые задачи, ручное подтверждение) — модель верная, ломает обход из review.
- Первая фраза сценария с раскрытием автоматизированного агента.
- Разделение отчёта на операционные / исходы / ограничения.
- Журнал действий как таблица время / событие / объект / описание.
- Отказ от force call и от выключения проверок.
- `index.html` как decision dashboard: не переписывать CJM, только связать кабинет с его этапами.
- Прослушивание аудио, обратная выгрузка, сложные интеграции, мультиязычность.

## G. Открытые вопросы

Только блокеры дизайна. Без них нельзя честно доработать экран.

1. Кто после автопаузы может нажать «Подтвердить возобновление» — `owner` / `collection_manager` / только `compliance_officer`? Без этого нельзя честно разметить кнопки. Источник: `prd-open-questions.md` §2.
2. Чем в UI является «Остановить кампанию», если в API нет `stopped` — `completed` или отдельный переход? Иначе модалка солжёт о последствиях.
3. Есть ли у звонка поле identity / third-party, или только транскрипт? Без поля нельзя рисовать статус верификации как факт.
4. Типы review-item в API: только `compliance` / `qa` / `risk` (`prd-open-questions.md` §6) или ещё handoff? Сейчас в прототипе `legal_review` и `manual_override` — не использовать, пока нет контракта.
5. Как в UI отличить sandbox от live, пока нет `legalBasisStatus`? Rulebook запрещает live без memo — нужен явный режим запуска, не догадка.

## H. Следующий шаг в `prototype.html`

Первыми тремя правками закрыть вход в путь, не расползаясь по всем экранам. Вносить в код только после явной команды.

1. **Главная и список кампаний** — риск и статус важнее KPI; у автопаузы CTA «Открыть причину».
2. **Глобальная очередь проверок** — та же таблица и drawer, что на вкладке «Проверка».
3. **Тестовый звонок не переводит в «работает»** + модалка запуска; review больше не вызывает `setCampaignState('running')`.
