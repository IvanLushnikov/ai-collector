## Зачем отдельный файл

UX-волна аудита `T-205`–`T-228` уже **закрыта** (риск в списке, тест≠запуск, review≠resume, readiness, импорт и т.д.).  
Этот бэклог — **следующая волна**: довести кабинет до плотности и ясности рыночных ops-кабинетов (Mango, Five9, FIS, Kit, Genesys, NICE, Talkdesk, Collect!), без AI-эстетики.

Канонический техбэклог (`TECH_BACKLOG_1SP.md`) остаётся общим реестром репозитория. Сюда не дублируем закрытые `T-*`. При переносе задачи в канон — поставить сюда `moved → T-XXX` и не брать повторно.

## Правила

- Одна задача = **1 SP**: узкий diff, понятный DoD, проверка за один проход.
- За проход брать **одну** `todo` (если явно не попросили больше).
- Тип: `design` (прототип/CSS/copy/IA) или `tech` (API/домен/тесты) или `both` (один экран, UI+данные).
- Статусы: `todo` / `doing` / `done` / `blocked` / `split` / `moved`.
- Не обходить compliance. Не обещать live без legal. Не копировать бренды референсов — только паттерны.
- Тексты только из `PRODUCT_LANGUAGE.md` (+ этот бэклог, если термин уже согласован с рынком и словарём).
