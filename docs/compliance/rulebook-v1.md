# Compliance rulebook v1

Дата: 17.08.2026  
Статус: продуктовый контур для кодирования и пилота, **не юридическое заключение**  
Владелец документа: продукт + compliance; юридический sign-off — отдельный шаг до live traffic  
Связанные документы: [PRD](../product/prd-draft.md), [карта технологий](../architecture/2026-08-17-technology-map.md), [автопауза](../operations/auto-pause.md), [ADR 0003](../decisions/0003-live-voice-provider.md), [ADR 0004](../decisions/0004-speech-llm-stack.md)

Источники норм в этом файле — уже зафиксированные артефакты репозитория (`index.html` на 14.08.2026, PRD, roadmap, PRODUCT_LANGUAGE, текущий код `src/compliance`). Если правило должно быть юридически точным, оно либо взято из этих источников, либо помечено `legal-confirm`.

## 1. Назначение

Rulebook отвечает на четыре вопроса:

1. Что система **обязана заблокировать** без участия LLM.
2. Что клиент **может сузить**, но не может выключить.
3. Что **нельзя** запускать в live, пока юрист не подтвердил.
4. Какой `reasonCode` и какой этап внедрения у каждого контроля.

Инвариант продукта: автоматизировать только то, что система может безопасно выполнить, объяснить и доказать.

## 2. Как применять

| Класс | Смысл | Можно ли выключить в UI |
|---|---|---|
| `system-lock` | Системная защита. Клиент не отключает. | Нет |
| `tenant-stricter` | Клиент может сделать **строже** системного минимума | Не шире минимума |
| `campaign-config` | Операционная настройка в пределах lock | Да, в пределах |
| `legal-confirm` | Не кодировать как «факт закона» и не пускать live, пока нет memo юриста | Не применимо |

Решение engine: `allow` или `block`. Третьего состояния «позвонить всё равно» нет. Override live-звонка не существует в v1.

Fail-closed: нет решения, нет правила, ошибка проверки, нет evidence на этапе, где оно обязательно → `block` / не стартовать вызов / автопауза.

`ruleVersion` пишется в каждый `ComplianceDecision`. Смена rulebook = новая версия, старые решения не переписываются.

## 3. Роли и ответственность

| Роль | Что делает rulebook |
|---|---|
| Кредитор / МФО | Оператор ПДн и сторона, инициирующая взыскание. Подтверждает основание контакта и актуальность базы. |
| Платформа | Обработчик по поручению. Исполняет lock-правила, пишет evidence, не подменяет compliance клиента. |
| Оператор связи / CPaaS | Маркировка, канал, запись по договору. Не принимает решение допуска. |
| LLM | Только после `allow` и только внутри state machine. Не судья ФЗ‑230. |

Вопрос «кто юридически инициирует вызов» остаётся в пакете юристам. До ответа live не запускается.

## 4. Каталог правил

Колонка «Код»: текущий код, если уже есть; иначе целевой код для внедрения.

### 4.1. Допуск до звонка (pre-dial)

#### R-CALL-WINDOW — окно времени

- **Класс:** `system-lock` + `tenant-stricter`
- **Источник продукта:** `index.html` / ФЗ‑230 ст. 7; код `CallWindowComplianceRule`
- **Системный минимум (продуктовая рамка):** местное время должника (`timezone` записи). Рабочие дни 08:00–22:00; выходные и нерабочие праздники 09:00–20:00.
- **Сейчас в коде:** будни `08:00–22:00`; суббота, воскресенье и продуктовый календарь нерабочих дней РФ 2026–2027 (`src/compliance/rules/russian-holidays.ts`) — `09:00–20:00`. Календарь — продуктовая рамка, не legal sign-off. Reason text не формулирует это как факт ФЗ‑230.
- **Код:** `CALL_WINDOW_BLOCK`
- **Клиент может:** сузить окно. Не может расширить за системный минимум.
- **Этап:** MVP Lab — текущее упрощение допустимо только для sandbox. Pilot — полное правило.
- **legal-confirm:** производственный календарь РФ и источник «места жительства/пребывания», если таймзона в файле не равна юридическому месту.

#### R-FREQUENCY — частота взаимодействий

- **Класс:** `system-lock` + `tenant-stricter`; лимиты как закон — `legal-confirm` на определение контакта
- **Источник продукта:** `index.html` — 1 / 2 / 8 (сутки / неделя / месяц) на кредитора и самостоятельное обязательство, не на кампанию
- **Системный минимум:** не больше продуктовой рамки 1/2/8 после legal sign-off. Клиент может задать меньше.
- **Счётчик:** frequency ledger `(tenantId, creditorKey, obligationId, bucket)`. Несколько кампаний одного кредитора делят лимит.
- **Код:** `FREQUENCY_LIMIT_BLOCK`
- **Этап:** Pilot. Pre-dial rule `FREQUENCY_LIMIT_BLOCK` есть (продуктовый cap 1/2/8). Инкремент sandbox ещё не исключён (`T-135`). Не формулировать как факт закона до memo.
- **legal-confirm до кодирования:** что считать состоявшимся контактом в состояниях `no_answer`, `busy`, `voicemail`, `ringing` без ответа, `failed`, короткие сбросы, перевод, повтор в той же сессии.

Консервативная продуктовая гипотеза до memo юриста (только для проектирования, не для live): в лимит попадает любая попытка, где абонентской стороне начал доставляться вызов (`ringing` и далее). Sandbox в лимит не входит.

#### R-DEBT-STATUS — статус обязательства

- **Класс:** `system-lock`
- **Источник:** доменная модель; код `DebtStatusRule`
- **Блок:** `closed`, `disputed`, `bankruptcy`, `contact_forbidden`
- **Код:** `DEBT_STATUS_BLOCK`
- **Клиент не может:** разрешить звонок по этим статусам.
- **Этап:** MVP Lab — есть. Pilot — нужна актуальность статуса (ручной re-import в v1).
- **Расширение Pilot (`legal-confirm` состав):** представитель, льготный период, ограничение дееспособности — отдельные статусы/списки, не свободный текст LLM.

#### R-CONSENT — статус согласия / отказа

- **Класс:** `system-lock`
- **Источник:** код `ConsentStatusRule`; 152‑ФЗ / ФЗ‑230 ст. 8 в продуктовой рамке
- **Сейчас в коде:** `given` → дальше другие правила; `revoked` → `CONSENT_REVOKED`; `pending` → `CONSENT_PENDING_BLOCK`.
- **Разрыв:** закрыт для pre-dial Lab/Pilot. Для live остаётся `legal-confirm`: покрывает ли согласие в договоре займа автоматические вызовы.
- **Целевое поведение Pilot, пока нет memo:** `given` → дальше другие правила; `revoked` → блок; `pending` → блок `CONSENT_PENDING_BLOCK`. **Внедрено.**
- **Клиент не может:** звонить при `revoked`.
- **legal-confirm:** покрывает ли согласие в договоре займа автоматические вызовы (коллизия с 126‑ФЗ ст. 44.1‑1).

#### R-SUPPRESSION — списки исключений

- **Класс:** `system-lock`
- **Источник:** roadmap / `index.html` (opt-out, уязвимые, запрет контакта)
- **Поведение:** номер, `externalId` или обязательство в suppression → `SUPPRESSION_BLOCK`
- **Этап:** Pilot. В MVP Lab частично закрыто через `contact_forbidden` / `revoked`.
- **Клиент может:** добавлять записи в список. Не может исключать системные статусы из проверки.
- **UI `blockKind` (OP-T-007):** `SUPPRESSION_BLOCK` → `permanent`; `CALL_WINDOW_BLOCK` / `FREQUENCY_LIMIT_BLOCK` → `temporary`. Пауза кампании (`campaign_pause`) — не строка suppression; отдельный ops-сценарий (статус кампании / `CAMPAIGN_JOB_BLOCKED`).

#### R-MARKING — маркировка и основание вызова

- **Класс:** `system-lock` для live; sandbox может идти без маркировки, если явно помечен как не-live
- **Источник:** 126‑ФЗ, ПП №1300, readiness UI
- **Поведение:** live launch и каждый live-звонок требуют активного соединения с подтверждённой маркировкой (`telephonyProbeResult`). Иначе `MARKING_UNAVAILABLE_BLOCK` / блок readiness.
- **Этап:** Pilot
- **legal-confirm:** текст отображаемого имени, договор с оператором, синхронизация операторского отказа абонента.

#### R-AUTO-DIAL-BASIS — основание автоматического вызова

- **Класс:** `legal-confirm` — **hard gate на live**
- **Источник:** коллизия ст. 44.1‑1 закона о связи и ФЗ‑230, зафиксированная в `index.html` и технологической карте
- **Поведение до memo:** live traffic запрещён. Sandbox и звонки на тестовые номера команды допустимы. Readiness: выбранное production-соединение + `legalBasisStatus≠confirmed` → `LEGAL_BASIS_NOT_CONFIRMED`. Sandbox-соединение legal basis не требует.
- **Код:** не внедрять обход. Readiness live = `blocked`, пока tenant не имеет `legalBasisStatus=confirmed` (поле появится после sign-off, не как самообслуживание менеджера кампаний).

#### R-STALE-DATA — устаревшая база

- **Класс:** `system-lock` на уровне процесса v1
- **Источник:** PRD (ручное обновление между импортом и звонком), roadmap
- **Поведение:** если после импорта менялись правила, сценарий или истёк согласованный TTL базы — readiness `stale`, новые звонки не стартуют.
- **Код:** `STALE_DATA_BLOCK` / readiness `stale`
- **Этап:** частично есть в readiness-summary. TTL числом — `campaign-config` после решения продукта, не выдумывать в этом файле.

### 4.2. Во время разговора

#### R-AI-DISCLOSURE — представление агента

- **Класс:** `system-lock`
- **Источник:** ФЗ‑230 ст. 7 в `index.html`; PRODUCT_LANGUAGE
- **Обязательные элементы первой реплики (продуктовая рамка):** факт, что говорит автоматизированный интеллектуальный агент; условное имя; ID агента; кредитор / представитель.
- **Клиент может:** задать имя агента и название организации в пределах шаблона. Не может убрать раскрытие и не может назвать агента «специалистом банка» без указания автоматизированного агента.
- **Код runtime:** `DISCLOSURE_MISSING` — если state machine не прошла шаг disclosure, дальнейшие tools с суммой долга запрещены; при срыве шага — завершение или handoff, не продолжение взыскания.
- **Этап:** MVP Lab — текст в прототипе. Pilot — runtime gate.

#### R-IDENTITY — верификация до раскрытия долга

- **Класс:** `system-lock` для live
- **Источник:** CJM и сценарий в `index.html`; вопрос юристам №3
- **Поведение:** до прохождения identity gate запрещены сумма долга, основание, реквизиты, давление к оплате. Допустимы представление агента и запрос подтверждения личности.
- **Код:** `IDENTITY_NOT_VERIFIED` как запрет tool, не как pre-dial block
- **Третье лицо / «это не я»:** никаких сведений о долге, вежливое завершение, `outcome` без disclosure. Код: `THIRD_PARTY_END`
- **legal-confirm:** достаточность конкретного call-flow идентификации для портфеля клиента.

#### R-NO-THIRD-PARTY — запрет раскрытия третьим лицам

- **Класс:** `system-lock`
- **Источник:** ФЗ‑230 ст. 6 в `index.html`
- **Поведение:** нет tool и нет промпт-разрешения сообщить долг кому-либо, кроме верифицированного должника. Отдельное согласие на третьих лиц в v1 **не реализуем**.
- **Этап:** Pilot

#### R-HANDOFF — продолжение с человеком

- **Класс:** `system-lock` для live
- **Источник:** ФЗ‑230; PRD fallback; автопауза `handoff_overloaded`
- **Обязательный перевод, если:** должник просит человека; модель ниже порога уверенности; спор личности/долга; жалоба; уязвимость; юридический вопрос вне сценария.
- **Поведение:** перевод на очередь/номер клиента с причиной и контекстом. Нельзя ответить «оставьте заявку на завтра», если очередь недоступна — только сценарий, подтверждённый юристом.
- **Если очереди нет:** новые звонки не стартуют (`HANDOFF_UNAVAILABLE_BLOCK`); активный разговор — безопасное завершение без продолжения взыскания + review.
- **Клиент может:** номер/SIP, часы очереди **не шире** окна R-CALL-WINDOW. Не может выключить handoff на live.
- **legal-confirm:** что делать вне часов очереди.

#### R-DIALOG-GUARDRAILS — содержание речи

- **Класс:** `system-lock`
- **Источник:** guardrails в `index.html`
- **Разрешено:** фактическая информация после identity; утверждённые формулировки; уточнение даты/суммы PTP; перевод.
- **Запрещено:** угрозы, стыд, давление, выдуманные последствия, обход отказа, самостоятельная реструктуризация, юрконсультация, hard collection.
- **Контроль:** state machine + allowlisted tools + golden/red-team набор. Не надеяться на «вежливый системный промпт».
- **Этап:** Pilot для runtime; MVP Lab — запрет в тексте сценария и QA.

#### R-LLM-NOT-JUDGE — граница модели

- **Класс:** `system-lock`
- **Поведение:** LLM не вызывает телефонию, не меняет compliance decision, не увеличивает лимиты, не обходит identity gate. Tools: `set_outcome`, `request_handoff`, `schedule_callback`, `end_call`, и только после gate — `confirm_ptp` с суммой/датой из БД, не из «памяти» модели.

### 4.3. Evidence, хранение, ПДн

#### R-AUDIT — доказуемость

- **Класс:** `system-lock`
- **Минимум на попытку:** кто/что инициировало; `ComplianceDecision` + `ruleVersion`; timestamps; статус телефонии; outcome; версия сценария/промпта/модели; handoff reason при переводе.
- **Потеря audit/logging на live:** автопауза, не «тихо продолжить».
- **Этап:** MVP Lab — decision log + audit действий. Pilot — полный bundle звонка.

#### R-RECORDING — запись и транскрипт

- **Класс:** `system-lock` для live; UI v1 может не давать прослушивание
- **Источник:** PRD (логирование и транскрипт); автопауза `recording_failed`
- **Поведение:** нет записи или нет транскрипта после отвеченного live-звонка → событие `recording_failed` → автопауза при пороге.
- **Sandbox:** может не иметь аудио, но это явно не live evidence.

#### R-RETENTION — срок хранения

- **Класс:** `legal-confirm` на срок; продуктовый ориентир из `index.html`: ≥ 1,5 года для обязанностей по ст. 17/17.1 ФЗ‑230 (изменения №137‑ФЗ)
- **Пока нет memo:** не удалять evidence пилота автоматически; не обещать клиенту конкретный срок в UI.
- **152‑ФЗ:** уничтожение по поручению после согласованного срока. Конфликт «хранить 1,5 года» vs «удалить по запросу» решает юрист, не engine.

#### R-LOCALIZATION — данные в РФ

- **Класс:** `system-lock` для live ПДн
- **Поведение:** PostgreSQL, object storage, ASR, TTS, LLM, логи с ПДн — в РФ или on-prem клиента. Зарубежный cloud LLM/ASR для должника запрещён.
- **Этап:** Pilot. Sandbox без реальных должников может использовать заглушки.

#### R-MINIMIZATION — минимум полей в модели

- **Класс:** `system-lock` для live
- **Поведение:** в ASR/LLM на шаге identity нет `debtAmount`. Сумма появляется только как tool-input после gate.
- **Запрет v1:** voiceprint / speaker identification / биометрия голоса.

#### R-NO-EXTRA-CHANNEL — постзвонковые сообщения

- **Класс:** `legal-confirm`
- **Источник:** вопрос юристам №8
- **Поведение v1:** не отправлять SMS/email/мессенджер после звонка, пока не подтверждено, что это не отдельное взаимодействие в лимите 1/2/8.

### 4.4. Кампания и остановка

#### R-STOP-AUTOPAUSE — защитная остановка

- **Класс:** `system-lock` + пороги `campaign-config` не ниже системного пола (пол порогов — отдельное продуктовое решение, здесь не выдумывается)
- **Коды из** `docs/operations/auto-pause.md`: `compliance_violation`, `complaint_spike`, `recording_failed`, `handoff_overloaded`, `provider_sla_failed`
- **Дополнительно для live:** потеря audit; маркировка недоступна; legal basis отозван.
- **Resume после auto-pause:** только safe-resume с owner/compliance_officer, не one-click. Нет force-call.

#### R-SCRIPT-VERSION — версия сценария

- **Класс:** `system-lock`
- **Поведение:** running-кампания не меняет активный сценарий на лету. Новая версия → `review` и повторный readiness. Юридические фразы disclosure locked в шаблоне.

#### R-PILOT-CAP — ограниченный запуск

- **Класс:** `campaign-config` внутри продуктовой рамки PRD
- **Рамка PRD:** ориентир 1 000–10 000 звонков/день как гипотеза пилота, не production-limit.
- **Поведение:** live без заданного cap и без sandbox-метки не стартует. Число cap задаёт пилот, не этот rulebook.

## 5. Что клиент настраивает в v1

| Можно | Нельзя |
|---|---|
| Сузить окно звонка | Расширить окно или звонить 24/7 |
| Уменьшить частоту относительно системного максимума | Поднять частоту выше lock |
| Имя агента, голос, темп, не-юридические формулировки | Убрать disclosure, назваться человеком |
| Номер/SIP перевода, лимит линий | Выключить handoff на live |
| Добавить suppression | Игнорировать bankruptcy/dispute/revoked |
| Текст сценария в шаблоне | Выключить compliance engine, force call |
| Порог уверенности не ниже системного пола | Отдать допуск звонка LLM |

Системный пол порога уверенности задаётся нами после замеров; до этого live handoff обязан существовать как обязательный путь, без тонкой настройки «выключить fallback».

## 7. Пакет юристу до pilot approval

Повторяет открытые вопросы продукта; rulebook их не закрывает.

1. Кто инициирует вызов и несёт ответственность: кредитор, платформа, оператор связи.
2. Что считается контактом для 1/2/8 в пограничных call-state.
3. Достаточен ли identity-flow до суммы долга.
4. Human continuation вне часов очереди и при перегрузе.
5. Срок хранения: ФЗ‑230 1,5 года vs 152‑ФЗ уничтожение vs политика МФО.
6. Какое согласие покрывает автоматические вызовы и как синхронизировать отказ у оператора связи.
7. Допустима ли success fee для выбранной договорной роли.
8. Являются ли SMS/ссылки после звонка отдельным взаимодействием.
9. Поля отчётности по 20‑ФЗ для МФО, когда появится форма.
10. Нужно ли блокировать `consentStatus=pending` на live.

## 8. Следствие для кода

Пока нет legal memo:

- не расширять `CallWindowComplianceRule` «как будто закон уже подтверждён в деталях выходных», если это выдаётся клиенту как юридический факт;
- не запускать live-провайдер в production mode без `R-AUTO-DIAL-BASIS`;
- не добавлять force-call;
- любой новый pre-dial контроль — через `ComplianceRule` + decision log + `ruleVersion`.
