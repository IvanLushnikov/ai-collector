- В `docs/security/rbac.md` уточнены права ролей для review-воркфлоу и ручных решений.

### D-010: Персистентность drilldown режима отчёта

Статус: `done`

Что сделать:

- Сохранять фильтры drilldown (`calls` / `review`) в query-параметрах при переходах из отчёта.
- Восстанавливать фильтры из URL при открытии вкладок `calls` и `review`.
- Поддерживать уже существующую персистентность роли отчёта.

Где менять:

- `prototype.html`

Критерии готовности:

- При клике по KPI/ссылкам отчёта открываются `calls` / `review` с сохранёнными в URL фильтрами.
- При прямом открытии вкладки `calls` / `review` с параметрами в URL применяются соответствующие фильтры в UI.
- Изменения состояния drilldown доступны после перезагрузки страницы и не ломают ранее добавленную роль-ориентированную логику отчёта.

### D-011: API-first вкладки `Calls` и карточки

Статус: `done`

Что сделать:

- Привязать список звонков в вкладке `calls` к API `GET /tenants/:tenantId/campaigns/:campaignId/calls`.
- Отображать явный статус источника данных (`live` / `демо`) в карточке состояния вкладки.
- В режиме API и сбоев API показывать корректный fallback на локальные мок-записи без потери drilldown и фильтров.
- Для карточки звонка в API-режиме показывать доступные поля из API и явно отмечать недоступность расширенной детализации до наличия `callAttemptId`.

Где менять:

- `prototype.html`
- `ROADMAP_B2B_SAAS.md`

Критерии готовности:

- `calls` больше не полностью локальный: при доступности API список строится из `GET /.../calls`.
- В `calls` есть явный индикатор источника данных и ошибка фолбэка при отсутствии API.
- Фильтры и drilldown из отчёта работают с API/демо-данными и корректно показывают пустые состояния.

### D-012: Поднять drill-down карточки звонка к `GET /calls/:callAttemptId`

Статус: `done`

Что сделать:

- Вернуть `callAttemptId` из `GET /tenants/:tenantId/campaigns/:campaignId/calls`.
- В `prototype.html` для API-записей с `callAttemptId` подгружать детальный блок карточки через `GET /tenants/:tenantId/campaigns/:campaignId/calls/:callAttemptId`.
- Поддержать явный fallback для записей, где `callAttemptId` отсутствует: ограничение transcript/recording/timeline с понятной подсветкой причины.

Где менять:

- `src/routes/calls.ts`
- `prototype.html`
- `tests/calls/sandbox-call.api.test.ts`

Критерии готовности:

- `GET /.../calls` возвращает `callAttemptId`, `prototype.html` использует его для drilldown.
- Для API-звонков с `callAttemptId` карточка показывает запись трансскрипта/записи/таймлайна после дополнительного запроса.
- Для API-звонков без `callAttemptId` отображается явное ограничение данных и корректный локальный/демо fallback.
