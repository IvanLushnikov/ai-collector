# Русские интерфейсные тексты AI-коллектора

## 1. Цель

Пиши для сотрудников финансовых организаций и взыскания, а не для разработчиков voice/LLM платформы.

Текст должен помогать принять решение и понимать риск.

## 2. Базовые правила

- коротко;
- конкретно;
- без канцелярита;
- без ненужных англицизмов;
- одно понятие — один термин;
- сначала итог, затем причина;
- действие называется действием;
- в рисковом сценарии явно сообщай последствия.

## 3. Доменные термины

Предпочитай термин продукта/отрасли, а не буквальный перевод API.

Возможные соответствия, если смысл совпадает:

- `campaign` → `кампания`;
- `debtor` → `должник` / `запись должника`;
- `call attempt` → `попытка звонка`;
- `conversation` → `разговор`;
- `business outcome` → `результат` / конкретный бизнес-результат;
- `review required` → `Требует проверки`;
- `handoff` → `Передать специалисту` / `Передано специалисту`;
- `decision log` → `История решений`;
- `audit log` → `Журнал действий` / `Аудит`;
- `auto-pause` → `Кампания приостановлена системой`, если термин `Автопауза` не закреплен;
- `voice provider` → `Провайдер звонков` / название интеграции;
- `compliance rule` → `Правило проверки`, если пользователь не работает термином compliance.

Не переименовывай `compliance` насильно для compliance officer: для него это нормальный профессиональный термин.

## 4. Технические термины

Для операционного интерфейса избегай:

- `LLM`;
- `ASR`;
- `TTS`;
- `orchestration`;
- `pipeline`;
- `payload`;
- `webhook`, если пользователь не администратор;
- `retry`;
- `validation failed`;
- raw rule codes.

Для технического admin UI отраслевые термины допустимы.

## 5. Кнопки

Кнопка предсказывает результат.

Хорошо:

- `Создать кампанию`
- `Загрузить базу`
- `Проверить данные`
- `Запустить тестовый обзвон`
- `Приостановить кампанию`
- `Остановить кампанию`
- `Передать на проверку`
- `Открыть решение`
- `Скачать отчет`
- `Повторить проверку`

Избегай:

- `ОК`;
- `Подтвердить`, если можно назвать действие;
- `Продолжить`, если следующий шаг конкретен;
- `Force` / `Ignore`.

## 6. Compliance copy

Начинай с результата.

Плохо:

`Compliance validation failed`

Лучше:

`Звонок не разрешен`

`Не выполнено обязательное условие для контакта.`

Точная причина должна приходить из продукта.

### Review

`Требуется проверка специалиста`

`Автоматический запуск звонка остановлен до принятия решения.`

Только если такое поведение реально.

## 7. Risk copy

Структура:

`Что произошло → что система сделала → что требуется`.

Пример формы:

`Кампания приостановлена системой. Новые звонки не запускаются. Проверьте событие перед возобновлением.`

Не используй ложное успокоение вроде `Ничего страшного`.

## 8. Ошибки

Ошибка должна отвечать:

1. Что не получилось?
2. Что произошло с операцией?
3. Что можно сделать?

Пример:

`Не удалось выполнить проверку перед звонком. Звонок не запущен. Повторите проверку.`

Не выводи HTTP status как основную ошибку.

## 9. Импорт

Хорошие формулировки:

- `Найдено 12 540 строк`
- `12 200 готовы к загрузке`
- `280 требуют исправления`
- `60 дубликатов`
- `Скачать строки с ошибками`

Не называй всю загрузку неуспешной, если большая часть данных обработана.

## 10. Пустые состояния

Пустое состояние объясняет, почему пусто и что дальше.

`Кампаний пока нет. Создайте первую кампанию для тестового запуска.`

`Звонков пока нет. Они появятся после запуска кампании.`

Для filtered state:

`По этим условиям ничего не найдено. Измените или сбросьте фильтры.`

## 11. Статусы

Статусы должны быть короткими и однородными.

Возможная грамматика:

- `Черновик`
- `Готова к запуску`
- `Запланирована`
- `Активна`
- `Требует проверки`
- `Приостановлена`
- `Завершена`
- `Остановлена`
- `Ошибка`

Финальные значения бери из backend.

Не смешивай в одном списке `Active`, `Запущено`, `На паузе`, `Complete`.

## 12. Подтверждения

Для опасного действия называй объект и последствия.

Плохо:

`Вы уверены? Да / Нет`

Лучше:

`Остановить кампанию «Просрочка 1–30 дней»? Новые звонки больше не будут запускаться.`

Кнопки:

`Остановить кампанию` / `Не останавливать`

Фактическое поведение бери из реализации.

## 13. Даты и числа

- `12 540` вместо `12540`;
- 24-часовой формат времени;
- русские формы множественного числа;
- единый формат дат внутри продукта;
- период отчета всегда видим.

Примеры:

- `1 звонок`
- `2 звонка`
- `5 звонков`
- `21 звонок`

## 14. Tone of voice

Предпочитай нейтральные инструкции:

`Проверьте данные перед запуском.`

`Исправьте 12 строк, чтобы добавить их в кампанию.`

Не используй рекламный тон внутри рабочего интерфейса.
