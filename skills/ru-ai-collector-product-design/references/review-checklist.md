# Финальный UX/UI review AI-коллектора

## Продуктовая модель

- [ ] Экран решает конкретную рабочую задачу.
- [ ] Не смешаны должник, попытка звонка, разговор и бизнес-результат.
- [ ] Compliance decision относится к конкретному действию/моменту.
- [ ] Audit events не подменены frontend-логикой.
- [ ] Sandbox-функции не выглядят production-ready.

## Controlled pilot

- [ ] Пользователь понимает, что запуск ограниченный.
- [ ] Перед запуском видна readiness-проверка.
- [ ] Блокирующие проблемы отличаются от предупреждений.
- [ ] Stop/review behavior объяснен только на основании продукта.
- [ ] Нет UX, создающего впечатление полностью автономного взыскания, если scope этого не допускает.

## Compliance

- [ ] Итог решения понятен.
- [ ] Причина решения доступна.
- [ ] Время решения доступно.
- [ ] Видно, к какому действию относится решение.
- [ ] Сработавшие проверки доступны нужной роли.
- [ ] Raw codes не являются основным объяснением.
- [ ] Нет обходной кнопки для blocked action без утвержденного override flow.
- [ ] Review и Blocked различаются.

## Risk / stop conditions

- [ ] Критический риск заметнее KPI.
- [ ] Понятно, что система сделала автоматически.
- [ ] Понятно, требуется ли действие пользователя.
- [ ] Auto-pause отличается от ручной паузы.
- [ ] Resume после риска не выглядит безопасным one-click действием, если нужен review.
- [ ] Потеря audit/logging не замаскирована под обычную ошибку, если это stop condition.

## Импорт

- [ ] Показан объем файла.
- [ ] Валидные и проблемные строки разделены.
- [ ] Дубликаты показаны отдельно, если определяются системой.
- [ ] Частичный успех не называется полной ошибкой.
- [ ] Пользователь может понять, что исправлять.

## Кампания

- [ ] Статус понятен.
- [ ] Главное действие соответствует текущему статусу.
- [ ] Видны risk/review states.
- [ ] Прогресс не смешан с business outcome.
- [ ] Pause / auto-pause / stop / complete различаются, если различаются в backend.

## Звонок

- [ ] Технический статус отделен от business outcome.
- [ ] Доступно связанное compliance decision.
- [ ] История попыток не перезаписывается одной записью.
- [ ] Risk/review события связаны со звонком.
- [ ] Техническая диагностика не перегружает обычного пользователя.

## Human review

- [ ] Понятно, почему объект передан человеку.
- [ ] Достаточно контекста для решения.
- [ ] Доступные действия имеют понятные последствия.
- [ ] Решение фиксируется в audit trail, если backend это поддерживает.
- [ ] Интерфейс не принимает решение вместо человека в human-review сценарии.

## Аналитика

- [ ] Метрики построены из реальных событий.
- [ ] Период видим.
- [ ] Denominator понятен.
- [ ] Debtors/calls/conversations/outcomes не смешаны.
- [ ] Compliance/risk метрики отделены от business outcomes.
- [ ] Нет mock KPI, выдаваемых за реальные.

## Русский текст

- [ ] Нет ненужных англицизмов.
- [ ] Технические термины не протекли в операционный UI.
- [ ] Кнопки называют действия.
- [ ] Ошибки объясняют судьбу операции.
- [ ] Рисковый текст объясняет последствия.
- [ ] Термины единообразны.
- [ ] Длинные русские строки не ломают layout.
- [ ] Plural forms корректны.

## Таблицы и формы

- [ ] Главные поля расположены первыми.
- [ ] Большой объем данных остается управляемым.
- [ ] Активные фильтры видны.
- [ ] Массовый выбор показывает точный scope.
- [ ] Label не заменен placeholder.
- [ ] Validation рядом с полем.
- [ ] После ошибки данные не теряются.
- [ ] Обязательная системная защита не выглядит выключаемой настройкой.

## Enterprise / security

- [ ] Tenant isolation не зависит от UI-фильтра.
- [ ] Permission state отличается от system error.
- [ ] Чувствительные данные показываются только нужной роли.
- [ ] Secrets не раскрываются.
- [ ] Нет придуманных ролей/permissions.
- [ ] Массовые и destructive действия подтверждаются пропорционально риску.

## Визуальная система

- [ ] Интерфейс похож на рабочую enterprise-систему, а не AI-лендинг.
- [ ] Критический статус не передается только цветом.
- [ ] Нет декоративных KPI/gauge без смысла.
- [ ] Не каждый блок завернут в карточку.
- [ ] Главное действие визуально одно.
- [ ] Использованы существующие компоненты/токены или минимальный базовый набор.

## Техническая проверка

- [ ] Нет invented API fields/statuses.
- [ ] Нет hardcoded compliance logic во frontend.
- [ ] Нет новой зависимости без причины.
- [ ] Нет дублирующих компонентов.
- [ ] i18n соблюден, если он есть.
- [ ] Tests / typecheck / lint выполнены в принятом объеме.
